
### 1. Общий принцип: компоненты как реализация функций СУБД

Состав компонентов СУБД непосредственно соответствует набору функций, рассмотренных в предыдущем вопросе: каждая функция (управление данными во внешней памяти, управление буферами, управление транзакциями, журнализация, поддержка языков БД и так далее) реализуется отдельным программным компонентом либо группой взаимодействующих компонентов. СУБД, таким образом, представляет собой не монолитную программу, а совокупность нескольких программных компонентов, каждый из которых нацелен на выполнение специфической, чётко очерченной задачи, при этом все компоненты взаимодействуют между собой по тщательно продуманным протоколам.

### 2. Укрупнённая структура СУБД

На верхнем уровне детализации в современной реляционной СУБД принято выделять четыре крупных, логически обособленных части.

**Ядро СУБД** (называемое также Data Base Engine) — основная резидентная часть СУБД, отвечающая за управление данными во внешней памяти, управление буферами оперативной памяти, управление транзакциями и журнализацию. Ядро обладает собственным, недоступным пользователям напрямую интерфейсом, которым пользуются программы, порождаемые компилятором языка БД, и утилиты СУБД. При использовании архитектуры «клиент — сервер» именно ядро составляет основную часть серверного компонента системы.

**Компилятор языка базы данных** (как правило, языка SQL) — преобразует конструкции языка определения и манипулирования данными в некоторый внутренний, обычно машинно-независимый исполняемый код.

**Подсистема поддержки времени выполнения** — интерпретирует программы манипулирования данными, порождённые компилятором, и обеспечивает пользовательский интерфейс взаимодействия с СУБД.

**Набор утилит** (сервисных программ) — внешние по отношению к ядру программные средства, обеспечивающие дополнительные возможности по обслуживанию информационной системы: загрузку и выгрузку данных, резервное копирование и восстановление, мониторинг производительности, реорганизацию хранимых структур и тому подобное.

### 3. Детализированная компонентная структура СУБД

Более подробная, обобщённая компонентная структура СУБД, детализирующая работу ядра и компилятора языка БД, включает следующие компоненты.

**Процессор запросов.** Преобразует поступивший запрос в последовательность низкоуровневых инструкций, направляемых далее контроллеру базы данных.

**Компилятор языка определения данных (ЯОД).** Преобразует конструкции ЯОД (описания схем отношений, ограничений целостности и тому подобного) в набор внутренних таблиц, содержащих метаданные, — то есть непосредственно наполняет словарь данных.

**Препроцессор языка манипулирования данными (ЯМД).** Преобразует операторы ЯМД, внедрённые в текст прикладных программ на базовом языке программирования, в вызовы стандартных функций этого базового языка; тем самым обеспечивается компиляция операторов языка БД в исполняемую программу.

**Контроллер словаря данных.** Управляет доступом к системному каталогу (словарю метаданных) и обеспечивает его согласованную работу; поскольку словарь данных, как отмечалось ранее, содержит описание структуры самой базы данных, этот компонент задействуется практически при выполнении любой операции над данными.

**Контроллер файлов.** Манипулирует файлами, предназначенными для хранения данных на внешних носителях, отвечает за распределение доступного дискового пространства, а также создаёт и поддерживает структуры и индексы, определённые во внутренней (физической) схеме базы данных.

**Контроллер базы данных.** Центральный компонент, взаимодействующий с прикладными программами и поступающими от пользователей запросами: он принимает запрос, сверяет его с внешними и концептуальной схемами базы данных для определения того, какие именно данные требуются для его выполнения, после чего обращается к контроллеру файлов для непосредственного извлечения или изменения данных. В состав контроллера базы данных, в свою очередь, входит ряд более узких программных компонентов:

- контроль прав доступа — проверяет наличие у пользователя полномочий на выполнение затребованной операции;
- процессор команд — принимает управление после успешной проверки полномочий и организует выполнение операции;
- средства контроля целостности — при выполнении операций, изменяющих содержимое базы данных, проверяют соблюдение всех установленных ограничений целостности;
- оптимизатор запросов — определяет наиболее эффективную (по времени выполнения либо иному критерию) стратегию выполнения запроса среди нескольких возможных;
- контроллер транзакций — осуществляет обработку операций, поступающих в рамках выполнения транзакций, обеспечивая соблюдение их атомарности;
- планировщик — управляет относительным порядком выполнения операций, затребованных различными параллельно выполняющимися транзакциями, обеспечивая их бесконфликтное совместное выполнение;
- контроллер восстановления — гарантирует приведение базы данных в непротиворечивое состояние при возникновении сбоев, опираясь на данные журнала;
- контроллер буфера — отвечает за перенос данных между оперативной памятью и внешним (как правило, дисковым) носителем.

### 4. Соответствие компонентов и функций СУБД

Нетрудно установить прямое соответствие между детализированными компонентами, перечисленными в разделе 3, и укрупнёнными функциями СУБД, рассмотренными в предыдущем вопросе: функция управления данными во внешней памяти реализуется контроллером файлов; функция управления буферами оперативной памяти — контроллером буфера; функция управления транзакциями — контроллером транзакций и планировщиком совместно; функция журнализации и восстановления — контроллером восстановления; функция обеспечения целостности данных — средствами контроля целостности; функция обеспечения безопасности — компонентом контроля прав доступа; функция поддержки языков БД — компилятором ЯОД и препроцессором ЯМД совместно с процессором запросов; наконец, функция поддержания словаря данных — контроллером словаря. Таким образом, компонентная структура СУБД представляет собой не произвольный набор программных модулей, а системную, взаимно согласованную реализацию всей совокупности функций, обязательных для полноценной системы управления базами данных.
