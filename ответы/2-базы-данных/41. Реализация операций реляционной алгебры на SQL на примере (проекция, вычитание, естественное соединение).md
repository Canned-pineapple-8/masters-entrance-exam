### 1. Общее замечание

Возможность выразить средствами SQL все примитивные операции реляционной алгебры (объединение, вычитание, декартово произведение, проекцию и ограничение), а через них — и все производные операции (пересечение, соединение, деление), служит доказательством реляционной полноты языка SQL: он обладает не меньшей выразительной силой, чем сама реляционная алгебра. Ниже рассматривается реализация трёх конкретных операций — проекции, вычитания и естественного соединения — на примере отношений `Поставщики(Номер_поставщика, Наименование_поставщика)`, `Детали(Номер_детали, Наименование_детали)` и `Поставки(Номер_поставщика, Номер_детали, Количество)`.

### 2. Операция проекции

Операции проекции $R[X, Y, \dots, Z]$, рассмотренной ранее в разделе о реляционной алгебре, в SQL соответствует непосредственно список столбцов, указываемый в предложении `SELECT`. Поскольку проекция по определению устраняет из результата полностью дублирующиеся строки, для точного (в теоретико-множественном смысле) соответствия результату операции проекции необходимо явно указывать модификатор `DISTINCT`; без него оператор `SELECT` возвращает мультимножество строк, допускающее дубликаты, что не вполне соответствует определению отношения как множества кортежей.

**Пример.** Отношению `Поставщики[Наименование_поставщика]` соответствует запрос:

```sql
SELECT DISTINCT Наименование_поставщика
FROM Поставщики;
```

Если требуется список из нескольких атрибутов, например проекция `Поставки[Номер_поставщика, Номер_детали]`:

```sql
SELECT DISTINCT Номер_поставщика, Номер_детали
FROM Поставки;
```

### 3. Операция вычитания (разности)

Операции вычитания $A\ \mathbf{MINUS}\ B$ двух совместимых по типу отношений в стандартном SQL соответствует оператор `EXCEPT` (именно под этим именем данная операция входит в стандарт SQL и реализована в PostgreSQL, Microsoft SQL Server и современных версиях MySQL); в СУБД Oracle исторически для этой же цели используется ключевое слово `MINUS` (в актуальных версиях Oracle также поддерживает `EXCEPT` как синоним). Оба варианта требуют, чтобы оба участвующих запроса возвращали одинаковое число столбцов совместимых типов, — то есть в точности требование совместимости по типу, рассмотренное ранее применительно к теоретико-множественным операциям реляционной алгебры. Как и подобает теоретико-множественной операции, результат автоматически не содержит дубликатов строк.

**Пример.** Пусть требуется найти поставщиков, которые зарегистрированы в отношении `Поставщики`, но ни разу не встречаются в отношении `Поставки` (то есть не осуществили ни одной поставки). Соответствующее выражение реляционной алгебры имеет вид `Поставщики[Номер_поставщика]\ \mathbf{MINUS}\ Поставки[Номер_поставщика]`, а на SQL (стандартный синтаксис, PostgreSQL, SQL Server) оно записывается так:

```sql
SELECT Номер_поставщика FROM Поставщики
EXCEPT
SELECT Номер_поставщика FROM Поставки;
```

Тот же запрос в диалекте Oracle:

```sql
SELECT Номер_поставщика FROM Поставщики
MINUS
SELECT Номер_поставщика FROM Поставки;
```

### 4. Операция естественного соединения

Операции естественного соединения $A\ \mathbf{JOIN}\ B$, рассмотренной ранее, в SQL может быть реализована тремя равносильными по смыслу, но синтаксически различными способами, поддержка которых, к сожалению, не вполне единообразна в разных СУБД.

**Ключевое слово `NATURAL JOIN`.** Наиболее прямое соответствие теоретической операции: соединение выполняется автоматически по всем одноимённым столбцам обеих таблиц, без необходимости явно их перечислять. Поддерживается в Oracle, PostgreSQL, MySQL и SQLite, но не поддерживается в Microsoft SQL Server.

```sql
SELECT *
FROM Поставки
NATURAL JOIN Поставщики;
```

**Конструкция `JOIN ... USING (список_столбцов)`.** Промежуточный по явности вариант: список общих столбцов, по которым выполняется соединение, указывается явно, что делает запрос более предсказуемым (не зависящим от случайного совпадения имён столбцов, не относящихся содержательно к связи между таблицами) и одновременно устраняет дублирование одноимённых столбцов в результате, как это происходит при обычном `JOIN ... ON`. Поддерживается в PostgreSQL и MySQL; не поддерживается в SQL Server.

```sql
SELECT *
FROM Поставки
JOIN Поставщики USING (Номер_поставщика);
```

**Явное указание условия соединения через `JOIN ... ON`.** Наиболее универсальный, переносимый между всеми СУБД (включая SQL Server) способ, требующий, однако, вручную перечислить условие равенства всех общих атрибутов и вручную исключить их дублирование в результирующем списке столбцов (поскольку `SELECT *` в этом случае вернул бы одноимённый столбец `Номер_поставщика` дважды — из обеих исходных таблиц):

```sql
SELECT Поставки.Номер_поставщика,
       Поставки.Номер_детали,
       Поставки.Количество,
       Поставщики.Наименование_поставщика
FROM Поставки
JOIN Поставщики ON Поставки.Номер_поставщика = Поставщики.Номер_поставщика;
```

Все три приведённых запроса содержательно эквивалентны и реализуют одну и ту же операцию естественного соединения; различие между ними — исключительно синтаксическое, обусловленное разной поддержкой сокращённых конструкций в конкретных диалектах SQL, поэтому выбор конкретного варианта на практике определяется используемой СУБД и требованиями переносимости кода.
