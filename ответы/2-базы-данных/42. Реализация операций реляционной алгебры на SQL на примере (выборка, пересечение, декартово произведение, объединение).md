### 1. Операция выборки (ограничения)

Операции выборки (ограничения) $R\ \mathbf{WHERE}\ z$, рассмотренной ранее, в SQL соответствует непосредственно предложение `WHERE` оператора `SELECT`: в него помещается то же самое логическое условие $z$, которому должны удовлетворять отбираемые строки. Дополнительно к обычным операторам сравнения SQL предоставляет ряд удобных предикатов, отсутствующих в исходной реляционной алгебре в явном виде, — `BETWEEN`, `IN`, `LIKE`, `IS NULL`, — но по сути являющихся лишь сокращённой записью составных логических условий.

**Пример.** Отношению `Поставки WHERE Количество > 100` соответствует запрос:

```sql
SELECT *
FROM Поставки
WHERE Количество > 100;
```

### 2. Операция пересечения

Операции пересечения $A\ \mathbf{INTERSECT}\ B$ двух совместимых по типу отношений в стандартном SQL соответствует одноимённый оператор `INTERSECT`, применяемый между двумя запросами `SELECT` с одинаковым числом столбцов совместимых типов — по аналогии с операторами `UNION` и `EXCEPT`, рассмотренными ранее. Как и подобает теоретико-множественной операции, результат не содержит дубликатов строк (если не указан отдельно поддерживаемый не всеми СУБД модификатор `INTERSECT ALL`).

Существен практический нюанс переносимости: оператор `INTERSECT` включён в стандарт SQL и поддерживается PostgreSQL, Oracle и Microsoft SQL Server (начиная с версии 2005), однако в СУБД MySQL он появился лишь начиная с версии 8.0.31 — в более ранних версиях MySQL операцию пересечения приходится эмулировать посредством `DISTINCT` в сочетании с `INNER JOIN` или посредством подзапроса с предикатом `IN`.

**Пример.** Пусть требуется найти поставщиков, зарегистрированных одновременно в двух совместимых по типу отношениях `Поставщики_Москва(Номер_поставщика, Наименование)` и `Поставщики_СПб(Номер_поставщика, Наименование)` (например, при слиянии двух региональных баз данных). Стандартный запрос:

```sql
SELECT * FROM Поставщики_Москва
INTERSECT
SELECT * FROM Поставщики_СПб;
```

Эквивалентный запрос, применимый в СУБД без поддержки `INTERSECT` (в частности, в ранних версиях MySQL):

```sql
SELECT DISTINCT М.*
FROM Поставщики_Москва М
INNER JOIN Поставщики_СПб С
  ON М.Номер_поставщика = С.Номер_поставщика
 AND М.Наименование = С.Наименование;
```

### 3. Операция декартова произведения

Операции декартова произведения $A\ \mathbf{TIMES}\ B$ в SQL соответствуют два равносильных синтаксических варианта. Первый — простое перечисление нескольких таблиц через запятую в предложении `FROM` при отсутствии условия `WHERE`, связывающего их столбцы. Второй, более явный и предпочтительный на практике, — оператор `CROSS JOIN`.

**Пример.** Декартову произведению `Поставщики TIMES Детали` соответствуют равносильные запросы:

```sql
SELECT *
FROM Поставщики, Детали;
```

```sql
SELECT *
FROM Поставщики
CROSS JOIN Детали;
```

Оба запроса возвращают все возможные сочетания строк обеих таблиц: если в `Поставщики` содержится $m$ строк, а в `Детали` — $n$ строк, результат содержит $m \cdot n$ строк, что в точности соответствует ранее установленному свойству мощности декартова произведения отношений. Существенно, что именно эта конструкция (декартово произведение, за которым логически следует выборка по условию связи, реализуемая предложением `WHERE`) лежит в основе классического, явного (не через `JOIN ... ON`) способа записи соединения таблиц в SQL — исторически более раннего, чем современный синтаксис с ключевым словом `JOIN`.

### 4. Операция объединения

Операции объединения $A\ \mathbf{UNION}\ B$ двух совместимых по типу отношений в SQL соответствует оператор `UNION`, применяемый между двумя запросами `SELECT`, возвращающими одинаковое число столбцов совместимых типов. По умолчанию `UNION` устраняет из результата дублирующиеся строки, в точности соответствуя теоретико-множественному определению объединения отношений, рассмотренному ранее. Если же требуется сохранить дубликаты (например, из соображений производительности, поскольку устранение дубликатов требует дополнительной сортировки или хеширования результата), используется модификатор `UNION ALL`, не соответствующий, строго говоря, определению теоретико-множественного объединения, но часто применяемый на практике, когда заведомо известно об отсутствии повторяющихся строк либо когда их сохранение не создаёт проблем для конкретной задачи.

**Пример.** Объединению `Поставщики_Москва UNION Поставщики_СПб` (полный список поставщиков из обоих регионов без повторений) соответствует запрос:

```sql
SELECT * FROM Поставщики_Москва
UNION
SELECT * FROM Поставщики_СПб;
```

Если же допустимо (или желательно) сохранение возможных дубликатов между двумя списками, используется:

```sql
SELECT * FROM Поставщики_Москва
UNION ALL
SELECT * FROM Поставщики_СПб;
```

### 5. Общее замечание о порядке выполнения

При совместном использовании нескольких из рассмотренных операторов (`UNION`, `INTERSECT`, `EXCEPT`) в одном составном запросе действует определённый приоритет их выполнения: оператор `INTERSECT` имеет более высокий приоритет и вычисляется раньше операторов `UNION` и `EXCEPT`, если порядок вычисления явно не переопределён скобками, — это правило аналогично приоритету умножения над сложением в обычных арифметических выражениях и должно учитываться при построении сложных запросов, комбинирующих сразу несколько теоретико-множественных операций.
