### 1. Общая характеристика первой нормальной формы

Первая нормальная форма (1НФ) — базовая, наиболее слабая нормальная форма отношения в реляционной модели данных. Формальное определение (восходящее к Э. Кодду) таково: переменная отношения находится в первой нормальной форме тогда и только тогда, когда в любом допустимом значении этой переменной каждый кортеж содержит ровно одно (атомарное) значение для каждого из атрибутов.

Существенная тонкость состоит в следующем: поскольку атомарность значений атрибутов заложена непосредственно в само определение отношения в реляционной модели (это было отмечено ранее при рассмотрении фундаментальных свойств отношений), всякое отношение, строго удовлетворяющее реляционной модели, по определению уже находится в первой нормальной форме — иными словами, объект, не удовлетворяющий требованию атомарности, вообще не является отношением в строгом смысле. Понятие «неатомарности» при этом само по себе не вполне однозначно: многие типы данных (строки, даты, числа с фиксированной точкой) могут быть при необходимости разложены на составляющие части средствами, предоставляемыми СУБД, и вопрос о том, где именно проходит граница «неделимости», в известной степени зависит от соглашений конкретной предметной области.

На практике, тем не менее, термин «приведение к 1НФ» употребляется в отношении так называемых ненормализованных таблиц (ННФ) — структур, ещё не являющихся отношениями в строгом смысле, поскольку в них присутствуют повторяющиеся группы данных: ячейки, содержащие сразу несколько значений, или наборы столбцов, дублирующих один и тот же по смыслу атрибут (например, «Телефон1», «Телефон2», «Телефон3»). Именно преобразование такой ненормализованной таблицы в полноценное отношение и составляет содержание процедуры приведения к 1НФ.
### 2. Практические требования первой нормальной формы

Обобщая изложенное, к таблице, приводимой к первой нормальной форме, предъявляются следующие требования: каждая ячейка таблицы должна содержать одно неделимое значение, а не список или составное значение; в таблице не должно быть повторяющихся групп атрибутов, то есть нескольких столбцов, предназначенных для хранения однотипных по смыслу значений; таблица должна обладать первичным ключом, однозначно идентифицирующим каждую строку и не принимающим неопределённых (NULL) значений, — что представляет собой прямое применение правила целостности сущностей, рассмотренного ранее; в таблице не должно быть полностью дублирующихся строк, а порядок следования строк и столбцов не должен иметь значения для смысла хранимых данных, — эти два последних требования, впрочем, автоматически выполняются для всякого подлинного отношения в силу его теоретико-множественной природы.
### 3. Способ приведения к 1НФ

Для устранения повторяющейся группы данных, найденной в ненормализованной таблице, применяется один из двух подходов.

**Первый подход (расширение строк).** В исходную таблицу добавляются дополнительные строки таким образом, чтобы в каждой строке каждый атрибут принимал ровно одно значение — то есть каждое из значений повторяющейся группы «разворачивается» в отдельную строку, при этом значения прочих атрибутов дублируются для каждой такой строки.

**Второй подход (декомпозиция).** Повторяющаяся группа выносится в отдельную, самостоятельную таблицу, связанную с исходной посредством внешнего ключа, ссылающегося на ключ исходной таблицы. Этот подход, как правило, предпочтительнее первого, поскольку не порождает избыточного дублирования значений прочих атрибутов исходной таблицы и сразу приводит структуру к виду, свободному от части аномалий, которые при первом подходе пришлось бы устранять на последующих этапах нормализации (при переходе ко 2НФ).
### 4. Пример приведения к 1НФ

Пусть дана исходная (ненормализованная) таблица «Заказы», в которой сведения о товарах, входящих в один заказ, перечислены в единой ячейке:

| Номер_заказа | Клиент | Товары (наименование, количество) |
| ------------ | ------ | --------------------------------- |
| 1            | Иванов | Болт (10), Гайка (5)              |
| 2            | Петров | Винт (3)                          |

Эта таблица не удовлетворяет требованию 1НФ, поскольку столбец «Товары» содержит для каждого заказа не одно, а сразу несколько значений (повторяющуюся группу пар «наименование — количество»), то есть значения этого столбца не являются атомарными.

**Приведение первым подходом (расширение строк):**

| Номер_заказа | Клиент | Товар | Количество |
|---|---|---|---|
| 1 | Иванов | Болт | 10 |
| 1 | Иванов | Гайка | 5 |
| 2 | Петров | Винт | 3 |

Полученная таблица формально удовлетворяет 1НФ (каждая ячейка содержит одно атомарное значение), однако ценой избыточного повторения значения атрибута «Клиент» для заказа №1, а первичным ключом теперь вынужденно становится составная пара (Номер\_заказа, Товар).

**Приведение вторым подходом (декомпозиция), обычно предпочтительное:** исходная таблица разбивается на два отдельных отношения —

`Заказы(Номер_заказа, Клиент)`

`Состав_заказа(Номер_заказа, Товар, Количество)`

— где атрибут `Номер_заказа` в отношении `Состав_заказа` выступает внешним ключом, ссылающимся на первичный ключ отношения `Заказы`. При таком подходе каждое из двух отношений сразу удовлетворяет требованию атомарности значений без дублирования сведений о клиенте, а связь между заказом и составляющими его товарами восстанавливается операцией естественного соединения `Заказы JOIN Состав_заказа`.
