### 1. Понятие хранимой процедуры

Хранимой процедурой называется объект базы данных, представляющий собой поименованный набор операторов SQL и процедурных расширений языка (управляющих конструкций, переменных), который компилируется однократно (при создании либо при первом вызове) и в скомпилированном виде хранится непосредственно на сервере СУБД, будучи в дальнейшем доступным для многократного вызова. Хранимые процедуры во многом аналогичны процедурам обычных языков программирования: они могут принимать входные и возвращать выходные параметры, содержать локальные переменные, выполнять числовые вычисления и операции над символьными и иными данными, а также использовать конструкции управления ходом выполнения — условные операторы (`IF`), циклы (`LOOP`, `WHILE`, `REPEAT`), множественный выбор (`CASE`), обработку курсоров для построчной обработки результата запроса. Внутри тела процедуры допустимо выполнение как операторов манипулирования данными (DML), так и, в большинстве СУБД, операторов определения данных (DDL), а также вызов других хранимых процедур.

Конкретная синтаксическая реализация хранимых процедур существенно различается между СУБД: в отличие от самого языка SQL, подчиняющегося единому стандарту, его процедурные расширения (Transact-SQL в Microsoft SQL Server, PL/SQL в Oracle, PL/pgSQL в PostgreSQL и другие) стандартом SQL не унифицированы, и одни и те же алгоритмические конструкции записываются в разных СУБД по-разному.

### 2. Параметры процедуры

При объявлении параметров хранимой процедуры для каждого из них указывается его тип по направлению передачи данных.

- `IN` (входной параметр, используемый по умолчанию, если направление не указано явно) — значение передаётся от вызывающей стороны в процедуру и используется в её теле лишь для чтения.
- `OUT` (выходной параметр) — значение вычисляется внутри процедуры и возвращается вызывающей стороне по завершении её работы; исходное значение, переданное при вызове (если таковое вообще предусмотрено синтаксисом конкретной СУБД), внутри процедуры не используется.
- `INOUT` (входной и выходной одновременно) — значение передаётся в процедуру, может быть изменено в её теле, и изменённое значение возвращается вызывающей стороне.

### 3. Отличие хранимых процедур от хранимых функций

Хранимые процедуры и хранимые функции (пользовательские функции, UDF) во многом схожи (обе представляют собой хранимый на сервере поименованный программный код), однако между ними имеется ряд принципиальных различий.

Функция обязана возвращать ровно одно значение указанного типа (в том числе, в ряде СУБД, таблицу — так называемая табличная функция), тогда как процедура, строго говоря, может не возвращать значение вовсе, ограничиваясь выполнением побочных действий (изменением данных) и, при необходимости, кодом состояния завершения (успех или неуспех) через выходные параметры.

Функцию можно вызывать непосредственно внутри SQL-выражения — например, в списке столбцов оператора `SELECT` или в условии `WHERE`, — тогда как процедура вызывается отдельным самостоятельным оператором (`CALL` в стандартном SQL и в PostgreSQL, `EXECUTE` в Transact-SQL) и не может быть встроена в качестве составной части выражения.

В большинстве СУБД на функцию накладываются дополнительные ограничения (в частности, запрет на изменение состояния базы данных операторами DML внутри тела функции), тогда как процедура подобных ограничений не имеет и свободно выполняет любые операции, включая изменение данных.

Заметим также, что в СУБД PostgreSQL истинные хранимые процедуры (объявляемые оператором `CREATE PROCEDURE`, способные самостоятельно управлять транзакциями внутри своего тела) появились относительно поздно; до этого их роль выполняли функции, объявленные с типом возвращаемого значения `void`.

### 4. Преимущества использования хранимых процедур

**Повышение производительности.** Поскольку хранимая процедура компилируется единожды и хранится на сервере в готовом (либо предварительно оптимизированном) виде, при каждом последующем вызове не требуется повторный синтаксический разбор и построение плана выполнения, что ускоряет обработку по сравнению с многократной отправкой одного и того же текста запроса.

**Снижение сетевого трафика.** Все входящие в процедуру операторы выполняются на сервере как единый пакет; по сети от клиента передаётся лишь вызов процедуры с фактическими значениями параметров, а не полный текст всех составляющих её операторов, что существенно сокращает объём передаваемых по сети данных при выполнении сложной, многошаговой логики обработки.

**Повышение безопасности.** Использование хранимых процедур позволяет ограничить или полностью исключить непосредственный доступ пользователей к таблицам базы данных: пользователю предоставляется лишь право на выполнение конкретной процедуры (посредством `GRANT EXECUTE`), реализующей строго определённый, контролируемый способ доступа к данным, минуя произвольные прямые операции над таблицами.

**Модульность и повторное использование кода.** Инкапсуляция часто используемой логики обработки данных в виде хранимой процедуры на стороне сервера позволяет многократно использовать один и тот же программный код из разных клиентских приложений, не дублируя его реализацию в каждом из них по отдельности, и упрощает сопровождение системы: изменение бизнес-логики требует правки в одном месте (в теле процедуры), а не во всех обращающихся к базе данных приложениях одновременно.

Существен также вопрос контекста выполнения прав доступа: хранимая процедура может быть выполнена либо с правами того, кто её создал (эта модель применяется по умолчанию в ряде СУБД), либо с правами того, кто её фактически вызвал, — выбор конкретной модели определяется настройками СУБД и объявлением самой процедуры и существенно влияет на то, какими именно правами реально должен обладать пользователь для успешного выполнения процедуры.

### 5. Системные хранимые процедуры

Многие СУБД поставляются с набором встроенных системных хранимых процедур, обеспечивающих программный интерфейс для работы с системными таблицами и служебной информацией СУБД (в частности, со словарём данных, рассмотренным ранее). В Microsoft SQL Server такие процедуры традиционно имеют префикс `sp_`, хранятся в системной базе данных и могут быть вызваны из контекста любой другой базы данных на том же сервере.

### 6. Пример синтаксиса

Упрощённый пример хранимой процедуры в диалекте PostgreSQL, принимающей входной параметр (номер отдела) и возвращающей через выходной параметр количество сотрудников этого отдела:

```sql
CREATE OR REPLACE PROCEDURE get_department_headcount(
    IN dept_name VARCHAR,
    OUT emp_count INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT COUNT(*) INTO emp_count
    FROM Сотрудники
    WHERE Отдел = dept_name;
END;
$$;
```

Вызов такой процедуры выполняется оператором `CALL`:

```sql
CALL get_department_headcount('Бухгалтерия', NULL);
```
