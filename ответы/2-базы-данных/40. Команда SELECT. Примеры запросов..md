### 1. Общий синтаксис оператора SELECT

Оператор `SELECT` — основной оператор языка запросов SQL, предназначенный для извлечения данных из одной или нескольких таблиц базы данных. Полный синтаксис оператора, в порядке его записи, выглядит следующим образом:

```sql
SELECT [DISTINCT] список_столбцов
FROM таблица [JOIN другая_таблица ON условие]
[WHERE условие_отбора_строк]
[GROUP BY список_столбцов_группировки]
[HAVING условие_отбора_групп]
[ORDER BY список_столбцов_сортировки [ASC|DESC]]
[LIMIT количество_строк [OFFSET смещение]]
```

Квадратные скобки обозначают необязательность соответствующей конструкции: обязательными являются лишь `SELECT` и `FROM` (последняя не требуется, только если источником данных служат исключительно константы или результаты вычисления выражений, не обращающиеся к таблицам).

### 2. Порядок записи и порядок логического выполнения

Существенная особенность оператора `SELECT`, часто становящаяся источником ошибок начинающих, состоит в том, что порядок записи его составляющих не совпадает с порядком их фактического (логического) выполнения. СУБД обрабатывает запрос в следующей последовательности:

1. `FROM` (и связанные с ним операции `JOIN`) — определение и формирование исходного набора строк-источников;
2. `WHERE` — построчная фильтрация полученного набора по заданному условию, выполняемая до какой-либо группировки;
3. `GROUP BY` — группировка отфильтрованных строк;
4. `HAVING` — фильтрация уже сформированных групп (в отличие от `WHERE`, условие в `HAVING` может содержать агрегатные функции);
5. `SELECT` — вычисление итогового списка столбцов (в том числе агрегатных функций и присвоение псевдонимов);
6. `ORDER BY` — сортировка итогового результата;
7. `LIMIT`/`OFFSET` — ограничение числа возвращаемых строк и смещение относительно начала результата.

Именно из этого расхождения между порядком записи и порядком выполнения вытекает, в частности, невозможность использовать в предложении `WHERE` агрегатную функцию (поскольку на момент выполнения `WHERE` группировка ещё не производилась) и, как правило, невозможность сослаться в `WHERE` или `GROUP BY` на псевдоним столбца, присвоенный в `SELECT` (поскольку сам список `SELECT` вычисляется позже).

### 3. Назначение отдельных предложений оператора SELECT

**`SELECT`** задаёт список возвращаемых столбцов (или выражений, вычисляемых на их основе); модификатор `DISTINCT` устраняет из результата полностью дублирующиеся строки; символ `*` означает выбор всех столбцов источника.

**`FROM`** указывает таблицу (или несколько таблиц, при необходимости — с использованием операции соединения `JOIN`), служащую источником данных для запроса.

**`WHERE`** задаёт условие, которому должны удовлетворять отдельные строки исходного набора данных, чтобы попасть в промежуточный результат, — соответствует ранее рассмотренной операции ограничения (выборки) реляционной алгебры.

**`GROUP BY`** группирует строки, имеющие одинаковые значения указанных столбцов, в одну итоговую строку — как правило, применяется совместно с агрегатными функциями, вычисляющими сводные значения (суммы, средние и тому подобное) для каждой такой группы.

**`HAVING`** задаёт условие отбора уже сформированных групп, аналогичное по роли предложению `WHERE`, но применяемое после группировки и допускающее использование агрегатных функций в условии.

**`ORDER BY`** задаёт порядок сортировки итогового результата по одному или нескольким столбцам, по возрастанию (`ASC`, по умолчанию) либо по убыванию (`DESC`).

**`LIMIT`/`OFFSET`** ограничивают число возвращаемых строк заданным количеством, при необходимости пропуская некоторое число строк с начала отсортированного результата (используется, в частности, для постраничного вывода данных).

### 4. Примеры запросов

Далее приведены примеры на условной схеме из двух связанных таблиц: `Сотрудники(Таб_номер, ФИО, Отдел, Зарплата)` и `Отделы(Отдел, Город_отдела)`.

**Простейшая выборка всех столбцов и строк:**

```sql
SELECT *
FROM Сотрудники;
```

**Выборка отдельных столбцов с условием отбора строк:**

```sql
SELECT ФИО, Зарплата
FROM Сотрудники
WHERE Зарплата > 50000;
```

**Выборка с сортировкой результата:**

```sql
SELECT ФИО, Зарплата
FROM Сотрудники
ORDER BY Зарплата DESC;
```

**Выборка с устранением дубликатов:**

```sql
SELECT DISTINCT Отдел
FROM Сотрудники;
```

**Соединение двух таблиц (естественное соединение по общему атрибуту `Отдел`):**

```sql
SELECT С.ФИО, С.Отдел, О.Город_отдела
FROM Сотрудники С
JOIN Отделы О ON С.Отдел = О.Отдел;
```

**Группировка с вычислением агрегатных значений:**

```sql
SELECT Отдел, COUNT(*) AS Число_сотрудников, AVG(Зарплата) AS Средняя_зарплата
FROM Сотрудники
GROUP BY Отдел;
```

**Группировка с последующей фильтрацией групп по агрегатному условию:**

```sql
SELECT Отдел, AVG(Зарплата) AS Средняя_зарплата
FROM Сотрудники
GROUP BY Отдел
HAVING AVG(Зарплата) > 60000;
```

**Запрос, объединяющий все рассмотренные предложения одновременно:**

```sql
SELECT С.Отдел, О.Город_отдела, COUNT(*) AS Число_сотрудников
FROM Сотрудники С
JOIN Отделы О ON С.Отдел = О.Отдел
WHERE С.Зарплата > 40000
GROUP BY С.Отдел, О.Город_отдела
HAVING COUNT(*) > 2
ORDER BY Число_сотрудников DESC
LIMIT 5;
```

Этот запрос последовательно (в порядке логического выполнения, а не записи) отбирает сотрудников с зарплатой выше 40000, соединяет их со сведениями об отделах, группирует по отделу и городу, оставляет лишь те группы, в которых более двух сотрудников, сортирует результат по убыванию числа сотрудников и возвращает не более пяти первых строк.

**Запрос с вложенным подзапросом:**

```sql
SELECT ФИО
FROM Сотрудники
WHERE Зарплата > (SELECT AVG(Зарплата) FROM Сотрудники);
```

Здесь вложенный (коррелированный по отношению к внешнему запросу) подзапрос вычисляет среднюю зарплату по всем сотрудникам, а внешний запрос отбирает тех сотрудников, чья зарплата превышает это вычисленное среднее значение.
