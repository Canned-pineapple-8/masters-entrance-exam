### 1. Общее назначение ER-модели

Модель «сущность — связь» (ER-модель, от англ. Entity-Relationship model), предложенная П. Ченом, представляет собой средство построения концептуальной модели предметной области на соответствующем этапе проектирования базы данных (см. предыдущий вопрос). Графическое представление этой модели называется ER-диаграммой; она строится из ограниченного набора базовых элементов — сущностей, атрибутов и связей, — каждый из которых характеризуется собственным набором свойств, рассматриваемых ниже.
### 2. Сущность

Сущностью (entity) называется класс однотипных объектов предметной области, обладающих одинаковым набором свойств (атрибутов), информация о которых подлежит хранению в базе данных. Различают тип сущности — само описание класса объектов (например, «Сотрудник», «Отдел», «Товар») — и экземпляр сущности — конкретный, отдельно взятый представитель этого класса (например, конкретный сотрудник с конкретными значениями атрибутов).

На диаграммах в нотации Чена сущность изображается прямоугольником с указанным внутри именем типа сущности.

### 3. Атрибут

Атрибутом сущности (или связи) называется свойство, характеризующее сущность (связь) и принимающее значения из некоторого множества. В формальной трактовке, восходящей к статье П. Чена, атрибут определяется как функция, отображающая множество экземпляров сущности (или связи) в множество значений либо в декартово произведение нескольких множеств значений. Так, атрибут «Возраст» отображает каждого сотрудника в конкретное числовое значение из набора возможных значений возраста, а составной атрибут «ФИО» отображает сотрудника в декартово произведение множеств значений «Имя», «Фамилия», «Отчество».

Множество допустимых значений, которые может принимать атрибут, называется доменом атрибута; домен — понятие семантическое, то есть он определяется не просто типом данных (числовой, строковый и так далее), а содержательным смыслом атрибута в предметной области, и разные атрибуты, использующие один и тот же тип данных, могут иметь разные домены.

Атрибуты классифицируются по нескольким независимым признакам. По структуре различают простые атрибуты (неделимые, например «Возраст») и составные атрибуты (состоящие из нескольких компонентов, например «Паспортные данные», объединяющие серию и номер). По множественности значений различают однозначные атрибуты (принимающие ровно одно значение для каждого экземпляра сущности) и многозначные атрибуты (способные принимать одновременно несколько значений, например «Номера телефонов»). По обязательности заполнения атрибуты делят на обязательные и необязательные. По изменчивости во времени различают статические атрибуты, значение которых не изменяется с течением времени (например, «Дата рождения»), и динамические атрибуты, значение которых может со временем изменяться (например, «Учёная степень»).

На диаграммах атрибут изображается в виде овала, соединённого линией с обозначающим сущность прямоугольником (в нотации Чена), либо перечисляется непосредственно внутри прямоугольника сущности (в ряде других нотаций); атрибуты, входящие в ключ сущности, принято выделять подчёркиванием.
### 4. Ключ сущности (идентификатор)

Ключом сущности (идентификатором) называется такая группа атрибутов, для которой отображение множества экземпляров сущности в соответствующую группу наборов значений является взаимно однозначным, то есть по значениям атрибутов ключа можно однозначно определить конкретный экземпляр сущности, и никакие два различных экземпляра не могут иметь одинаковый набор значений ключевых атрибутов. Если для сущности возможно указать несколько таких групп атрибутов (потенциальных ключей), один из них выбирается в качестве основного (первичного) ключа, а остальные считаются альтернативными ключами.

### 5. Связь

Связью (relationship) называется некоторая содержательная ассоциация между двумя сущностями либо между сущностью и ею самой (в этом случае связь называется рекурсивной, или рефлексивной). На диаграммах в нотации Чена связь изображается ромбом, соединённым линиями с участвующими в ней прямоугольниками сущностей, с указанным внутри ромба именем связи.

Связь характеризуется двумя основными параметрами: степенью и классом принадлежности участвующих в ней сущностей.

**Степень (мощность) связи** — это число типов сущностей, участвующих в образовании данной связи. Связь, соединяющая один тип сущности с самим собой, называется унарной (рекурсивной); связь, соединяющая два различных типа сущности, называется бинарной, — это наиболее распространённый на практике случай; связь, соединяющая три типа сущности одновременно, называется тернарной, и так далее.

**Класс принадлежности (кардинальность участия)** сущности в связи показывает, обязан ли каждый без исключения экземпляр данной сущности участвовать в этой связи, или же участие является необязательным. Например, если в каждом отделе организации обязательно должен быть руководитель, то каждому экземпляру сущности «Отдел» непременно соответствует связанный с ним экземпляр сущности «Сотрудник» — здесь класс принадлежности сущности «Отдел» в этой связи обязателен. При этом не каждый сотрудник является руководителем какого-либо отдела, то есть класс принадлежности сущности «Сотрудник» в той же связи, напротив, необязателен.

### 6. Типы связей по кардинальности (степени соответствия)

Наиболее важной для проектирования базы данных характеристикой бинарной связи является тип соответствия между количеством экземпляров одной и другой участвующих сущностей. Различают три основных типа связей.

**Связь «один к одному» (1:1).** Каждый экземпляр первой сущности связан не более чем с одним экземпляром второй сущности, и наоборот. Пример: связь между сущностями «Пассажир рейса» и «Посадочное место» — конкретному пассажиру соответствует ровно одно место, и конкретное место в данном рейсе занимает не более одного пассажира.

**Связь «один ко многим» (1:N).** Один экземпляр первой сущности может быть связан с произвольным числом экземпляров второй сущности, тогда как каждый экземпляр второй сущности связан не более чем с одним экземпляром первой. Пример: связь между сущностями «Клиент» и «Заказ» — один клиент может сделать множество заказов, но каждый конкретный заказ принадлежит ровно одному клиенту. Аналогично, связь между сущностями «Компания» и «Сотрудник» (в одной компании работает много сотрудников, но каждый сотрудник работает ровно в одной компании) — связь типа «один ко многим».

**Связь «многие ко многим» (M:N).** Произвольное число экземпляров первой сущности может быть связано с произвольным числом экземпляров второй сущности, и наоборот. Пример: связь между сущностями «Студент» и «Курс» — один студент может быть записан на несколько курсов, и на каждый курс записывается множество студентов. При реализации подобной связи средствами реляционной модели данных, как правило, требуется введение дополнительной (связующей) таблицы, содержащей пары ключей связываемых сущностей, поскольку прямое представление связи «многие ко многим» посредством внешнего ключа в одной из исходных таблиц невозможно.

### 7. Замечание о нотациях

Помимо исходной нотации Чена (прямоугольники для сущностей, овалы для атрибутов, ромбы для связей, все элементы соединяются линиями), на практике распространены и другие графические нотации построения ER-диаграмм — в частности, нотация Мартина (называемая также нотацией «вороньей лапки», Crow's Foot), в которой атрибуты перечисляются непосредственно внутри прямоугольника сущности, а тип связи (1:1, 1:N, M:N) обозначается специальными символами на концах соединяющей линии, а не отдельной геометрической фигурой. Содержательный смысл всех перечисленных выше элементов и типов связей при этом остаётся неизменным вне зависимости от выбранной нотации — различия носят исключительно графический характер.
