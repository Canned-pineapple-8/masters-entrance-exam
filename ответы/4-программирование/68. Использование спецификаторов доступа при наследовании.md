### 1. Общий синтаксис

При объявлении производного класса конкретный способ наследования указывается посредством спецификатора доступа, помещаемого перед именем базового класса:

```c++
class Derived : specifier Base {
    // ...
};
```

где `specifier` принимает одно из трёх значений — `public`, `protected` или `private`. Если спецификатор явно не указан, по умолчанию для наследования, объявленного ключевым словом `class`, подразумевается `private`, а для наследования, объявленного ключевым словом `struct`, — `public` (по аналогии с умолчанием, действующим для доступа к обычным членам класса, рассмотренным в предыдущем вопросе).

Выбор конкретного спецификатора определяет, каким образом уровни доступа к унаследованным от базового класса членам преобразуются применительно к производному классу.

### 2. Правило преобразования уровней доступа

Общее правило таково: элементы базового класса, объявленные `private`, никогда не становятся напрямую доступными в производном классе, вне зависимости от выбранного спецификатора наследования, — обратиться к ним из кода производного класса можно исключительно опосредованно, через открытые или защищённые методы самого базового класса (то есть они по-прежнему физически присутствуют в объекте производного класса, но недоступны по имени напрямую). Элементы, объявленные `protected` или `public`, напротив, преобразуются в соответствии с выбранным спецификатором наследования согласно следующей таблице.

| Доступ в базовом классе | `public`-наследование | `protected`-наследование | `private`-наследование |
|---|---|---|---|
| `public` | `public` | `protected` | `private` |
| `protected` | `protected` | `protected` | `private` |
| `private` | недоступен | недоступен | недоступен |

Иными словами, при `public`-наследовании уровни доступа к унаследованным членам сохраняются в точности такими же, какими они были объявлены в базовом классе; при `protected`-наследовании все ранее публичные члены становятся защищёнными (а защищённые остаются защищёнными); при `private`-наследовании все ранее публичные и защищённые члены становятся закрытыми членами производного класса.

### 3. Публичное (`public`) наследование

Наиболее часто применяемый на практике вид наследования, моделирующий отношение «является разновидностью» (is-a) между производным и базовым классом: объект производного класса с полным основанием может рассматриваться (и использоваться, в частности, через указатель или ссылку на базовый класс — см. вопрос о полиморфизме) как объект базового класса.

```c++
class Base {
public:
    int a;
protected:
    int b;
private:
    int c;
};

class PublicDerived : public Base {
    // a остаётся public
    // b остаётся protected
    // c недоступен напрямую
};
```

### 4. Защищённое (`protected`) наследование

Применяется существенно реже, преимущественно в тех случаях, когда предполагается дальнейшая, многоуровневая иерархия наследования, и требуется предоставить доступ к унаследованным (в том числе исходно публичным) членам лишь последующим, ещё более производным классам, полностью скрыв их при этом от произвольного стороннего кода, обращающегося к объекту производного класса «снаружи».

```c++
class ProtectedDerived : protected Base {
    // a становится protected
    // b остаётся protected
    // c недоступен напрямую
};
```

### 5. Закрытое (`private`) наследование

При закрытом наследовании все унаследованные публичные и защищённые члены базового класса становятся закрытыми членами производного класса — то есть доступными лишь внутри самого производного класса (и, при дальнейшем наследовании от него, недоступными уже и следующему за ним производному классу, поскольку закрытые члены, как было отмечено выше, не наследуются напрямую в принципе). Закрытое наследование моделирует не отношение «является разновидностью», а скорее отношение «реализован посредством» (implemented-in-terms-of): производный класс внутренне использует функциональность базового класса для собственной реализации, но не предоставляет её как часть своего собственного публичного интерфейса, и, в частности, объект такого производного класса нельзя неявно преобразовать к типу базового класса извне.

```c++
class PrivateDerived : private Base {
    // a становится private
    // b становится private
    // c недоступен напрямую
};
```

На практике отношение «реализован посредством» чаще моделируется не закрытым наследованием, а простой композицией (включением объекта одного класса в качестве поля другого), поскольку композиция обеспечивает более чёткое разделение ответственности между классами; закрытое наследование сохраняет практическую ценность преимущественно в тех специфических случаях, когда производному классу требуется прямой доступ к защищённым членам базового класса либо возможность переопределения его виртуальных функций, что композиция обеспечить не позволяет.
### 6. Итоговое замечание

Выбор спецификатора доступа при наследовании, таким образом, представляет собой самостоятельное архитектурное решение, независимое от исходных модификаторов доступа, объявленных внутри самого базового класса: он определяет не то, какие члены физически наследуются производным классом (наследуются, с оговоркой о невозможности прямого именованного доступа, все нестатические члены базового класса независимо от их исходного модификатора доступа), а то, какой уровень доступа к этим унаследованным членам будет предоставлен коду, работающему с объектом производного класса — как изнутри последующих производных классов, так и извне всей иерархии наследования.
