### 1. Сортировка пузырьком (bubble sort)

Простейший алгоритм сортировки, основанный на многократном сравнении и обмене соседних элементов массива, нарушающих требуемый порядок. За каждый полный проход по массиву наибольший из ещё не отсортированных элементов «всплывает» на своё окончательное место в его конце — отсюда и название алгоритма.

```c++
void BubbleSort(std::vector<int>& arr) {
    size_t n = arr.size();
    for (size_t i = 0; i < n - 1; ++i) {
        bool swapped = false;
        for (size_t j = 0; j < n - 1 - i; ++j) {
            if (arr[j] > arr[j + 1]) {
                std::swap(arr[j], arr[j + 1]);
                swapped = true;
            }
        }
        if (!swapped) break;   // массив уже отсортирован — досрочное завершение
    }
}
```

Трудоёмкость алгоритма в среднем и в худшем случае составляет $O(n^2)$, в лучшем случае (уже отсортированный массив, при наличии проверки `swapped`) — $O(n)$. Сортировка пузырьком устойчива (сохраняет относительный порядок равных элементов) и выполняется на месте, без дополнительной памяти, однако на практике ввиду низкой эффективности применяется преимущественно в учебных целях.
### 2. Сортировка слиянием (merge sort)

Алгоритм типа «разделяй и властвуй»: массив рекурсивно делится пополам вплоть до тривиальных подмассивов из одного элемента (заведомо упорядоченных), после чего пары соседних уже отсортированных подмассивов последовательно сливаются (объединяются с сохранением порядка) в единый, больший отсортированный массив.

```c++
void Merge(std::vector<int>& arr, int left, int mid, int right) {
    std::vector<int> temp;
    int i = left, j = mid + 1;
    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) temp.push_back(arr[i++]);
        else                  temp.push_back(arr[j++]);
    }
    while (i <= mid)  temp.push_back(arr[i++]);
    while (j <= right) temp.push_back(arr[j++]);
    for (int k = 0; k < static_cast<int>(temp.size()); ++k) {
        arr[left + k] = temp[k];
    }
}

void MergeSort(std::vector<int>& arr, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    MergeSort(arr, left, mid);
    MergeSort(arr, mid + 1, right);
    Merge(arr, left, mid, right);
}
```

Трудоёмкость сортировки слиянием гарантированно составляет $O(n \log n)$ независимо от исходного порядка элементов входного массива — в отличие от рассматриваемой ниже быстрой сортировки, эта оценка не имеет квадратичного худшего случая. Алгоритм устойчив, однако требует дополнительной памяти порядка $O(n)$ для вспомогательного массива, используемого на этапе слияния.
### 3. Сортировка подсчётом (counting sort)

Принципиально отличный от рассмотренных выше алгоритм: в отличие от них, сортировка подсчётом не производит непосредственного сравнения элементов между собой, а опирается на подсчёт числа вхождений каждого конкретного значения в исходном массиве. Применение алгоритма целесообразно лишь тогда, когда сортируемые числа принадлежат заранее известному, достаточно узкому диапазону значений $[0, k-1]$, сравнимому по величине с числом самих сортируемых элементов $n$.

```c++
void CountingSort(std::vector<int>& arr, int maxValue) {
    std::vector<int> count(maxValue + 1, 0);
    for (int x : arr) {
        ++count[x];              // подсчёт числа вхождений каждого значения
    }
    for (int i = 1; i <= maxValue; ++i) {
        count[i] += count[i - 1]; // накопленные суммы — префиксные суммы
    }
    std::vector<int> result(arr.size());
    for (int i = static_cast<int>(arr.size()) - 1; i >= 0; --i) {
        result[--count[arr[i]]] = arr[i];   // размещение с конца — обеспечивает устойчивость
    }
    arr = result;
}
```

Трудоёмкость алгоритма составляет $O(n + k)$, где $n$ — число сортируемых элементов, а $k$ — размер диапазона возможных значений; при $k = O(n)$ это даёт линейную по $n$ трудоёмкость, недостижимую для алгоритмов сортировки, основанных на попарном сравнении элементов (для которых доказана нижняя граница $\Omega(n \log n)$). При корректной реализации (размещение элементов с конца массива, как показано выше) сортировка подсчётом устойчива. Существенный недостаток метода — практическая неприменимость при большом диапазоне возможных значений $k$, поскольку в этом случае как затраты памяти на вспомогательный массив счётчиков, так и время его обработки становятся неоправданно велики.

### 4. Быстрая сортировка Хоара (quicksort)

Алгоритм, разработанный Ч. Хоаром в 1960 году, также относится к методам типа «разделяй и властвуй» и состоит из трёх шагов: выбор из массива опорного элемента; разбиение (партиционирование) массива на две части — элементы, меньшие опорного, и элементы, не меньшие его; и рекурсивное применение той же процедуры к каждой из полученных частей.

Классическая, наиболее эффективная схема разбиения — схема Хоара — использует два индекса, движущихся навстречу друг другу с противоположных концов обрабатываемого участка массива, вплоть до обнаружения пары «неправильно» расположенных элементов (элемента, большего опорного, слева, и элемента, меньшего опорного, справа), которые затем меняются местами.

```c++
int HoarePartition(std::vector<int>& arr, int lo, int hi) {
    int pivot = arr[lo];
    int i = lo - 1;
    int j = hi + 1;
    while (true) {
        do { ++i; } while (arr[i] < pivot);
        do { --j; } while (arr[j] > pivot);
        if (i >= j) return j;
        std::swap(arr[i], arr[j]);
    }
}

void QuickSort(std::vector<int>& arr, int lo, int hi) {
    if (lo < hi) {
        int p = HoarePartition(arr, lo, hi);
        QuickSort(arr, lo, p);
        QuickSort(arr, p + 1, hi);
    }
}
```

Схема разбиения Хоара существенно эффективнее внешне более простой и часто приводимой в учебниках схемы Ломуто (использующей единственный индекс и выбирающей опорным элементом последний элемент участка): в среднем схема Хоара выполняет втрое меньше обменов элементов и остаётся эффективной даже при наличии в массиве большого числа одинаковых элементов, тогда как схема Ломуто в этом случае, как и на уже отсортированном массиве, деградирует до квадратичной трудоёмкости.

В среднем случае трудоёмкость быстрой сортировки составляет $O(n \log n)$, что на практике делает её одним из самых быстродействующих алгоритмов сортировки общего назначения; в худшем случае (при систематически неудачном выборе опорного элемента, приводящем к максимально несбалансированному разбиению на каждом шаге — в частности, на уже отсортированном массиве при выборе опорным крайнего элемента) трудоёмкость деградирует до $O(n^2)$. Для снижения вероятности возникновения такого худшего случая на практике опорный элемент нередко выбирают случайным образом либо как медиану первого, среднего и последнего элементов обрабатываемого участка. Дополнительные затраты памяти алгоритма (на стек рекурсивных вызовов) составляют $O(\log n)$ в среднем случае; сортировка выполняется на месте (не требует вспомогательного массива для хранения результата, в отличие от сортировки слиянием), однако, в отличие от неё, неустойчива — не гарантирует сохранения относительного порядка равных по значению элементов.
