### 1. Понятие полиморфизма

Полиморфизмом (от греческого «многоформенность») в программировании называется свойство, позволяющее использовать единый интерфейс (одно и то же имя функции, оператора или метода) для работы с объектами различных типов данных, при этом фактическое поведение этого интерфейса определяется либо типом переданных аргументов, либо реальным (динамическим) типом обрабатываемого объекта. Полиморфизм составляет один из трёх фундаментальных принципов объектно-ориентированного программирования, наряду с инкапсуляцией и наследованием.

Согласно классификации, восходящей к работам К. Стрэчи, различают несколько разновидностей полиморфизма: полиморфизм включения (subtype polymorphism), реализуемый посредством наследования и виртуальных функций; параметрический полиморфизм, реализуемый посредством обобщённого программирования (шаблонов, дженериков); и специальный (ad hoc) полиморфизм, реализуемый посредством перегрузки функций и операторов. В сообществе языка C++ принято более узкое, практическое деление на две категории: статический (compile-time) полиморфизм, объединяющий перегрузку и шаблоны и разрешаемый компилятором ещё на этапе компиляции программы, и динамический (runtime) полиморфизм, основанный на наследовании и виртуальных функциях и разрешаемый лишь во время выполнения программы.
### 2. Статический полиморфизм

**Перегрузка функций.** Позволяет определить в программе несколько функций с одним и тем же именем, но с различным набором (числом или типами) параметров; компилятор, анализируя типы фактически переданных аргументов на этапе компиляции, самостоятельно выбирает, какую из перегруженных версий функции вызвать в конкретном месте программы.

```c++
void Print(int value) {
    std::cout << "Целое число: " << value << "\n";
}

void Print(double value) {
    std::cout << "Вещественное число: " << value << "\n";
}

void Print(const std::string& value) {
    std::cout << "Строка: " << value << "\n";
}
```

При вызове `Print(5)`, `Print(3.14)` и `Print("hello")` компилятор подставит соответственно первую, вторую и третью версии функции, исходя из типа переданного аргумента, — притом это решение принимается полностью на этапе компиляции, без какого-либо дополнительного времени выполнения на определение нужной версии.

**Перегрузка операторов.** Частный случай перегрузки функций, позволяющий переопределить поведение стандартных операторов языка (`+`, `<<`, `==` и других) применительно к пользовательским типам данных.

```c++
class Vector2D {
public:
    double x, y;
    Vector2D operator+(const Vector2D& other) const {
        return Vector2D{x + other.x, y + other.y};
    }
};
```

**Шаблоны (параметрический полиморфизм).** Позволяют написать единый обобщённый код функции или класса, оперирующий параметром-типом, конкретное значение которого подставляется компилятором при инстанцировании (порождении) шаблона для каждого фактически использованного в программе типа.

```c++
template <typename T>
T Max(T a, T b) {
    return (a > b) ? a : b;
}
```

При вызовах `Max(3, 5)` и `Max(2.5, 1.7)` компилятор самостоятельно порождает («инстанцирует») из этого единого шаблона две различные, специализированные функции — для типа `int` и для типа `double` соответственно, — подставляя нужную версию уже на этапе компиляции; именно поэтому полиморфизм на основе шаблонов также относят к статическому.

### 3. Динамический полиморфизм

В основе динамического полиморфизма лежит различие между статическим и динамическим связыванием вызова функции с её конкретной реализацией. При статическом связывании (применяемом по умолчанию для обычных, не виртуальных функций) соответствие вызова конкретной реализации устанавливается уже на этапе компиляции, исходя из объявленного (статического) типа переменной, через которую производится вызов. При динамическом связывании, возможном лишь для функций, объявленных с ключевым словом `virtual`, и только при обращении к объекту через указатель или ссылку на базовый класс, конкретная вызываемая реализация определяется не объявленным типом указателя (ссылки), а фактическим (динамическим) типом объекта, на который этот указатель или ссылка в действительности указывает, — причём это определение выполняется уже во время выполнения программы.

```c++
class Animal {
public:
    virtual std::string Voice() const {
        return "...";
    }
    virtual ~Animal() = default;
};

class Cat : public Animal {
public:
    std::string Voice() const override {
        return "Meow!";
    }
};

class Dog : public Animal {
public:
    std::string Voice() const override {
        return "Woof!";
    }
};

void Process(const Animal& creature) {
    std::cout << creature.Voice() << "\n";
}

int main() {
    Cat c;
    Dog d;
    Process(c);   // выведет "Meow!"
    Process(d);   // выведет "Woof!"
}
```

В приведённом примере функция `Process` принимает параметр типа `const Animal&` (ссылку на базовый класс), однако фактически вызываемая реализация метода `Voice` определяется не типом параметра, объявленным в сигнатуре функции, а истинным типом переданного объекта (`Cat` или `Dog`) — именно в этом и заключается содержательный смысл динамического полиморфизма: один и тот же вызывающий код `Process` единообразно работает с объектами любого производного от `Animal` класса, не зная заранее об их конкретных типах.

Механически динамическое связывание реализуется компилятором посредством таблицы виртуальных методов (vtable): каждый полиморфный класс (класс, содержащий хотя бы одну виртуальную функцию) снабжается собственной такой таблицей, содержащей адреса его виртуальных функций, а каждый объект этого класса — скрытым указателем на соответствующую таблицу; вызов виртуальной функции транслируется компилятором в косвенное обращение через этот указатель и таблицу, что и обеспечивает выбор нужной реализации уже во время выполнения программы, ценой небольших дополнительных накладных расходов по сравнению со статическим связыванием.

Существенное практическое правило, вытекающее из механизма динамического полиморфизма: если базовый класс содержит виртуальные функции и предполагается полиморфная работа с объектами производных классов через указатель на базовый класс (в частности, с удалением объекта, размещённого в динамической памяти, через такой указатель), деструктор базового класса также обязательно должен быть объявлен виртуальным (как показано в примере выше, `virtual ~Animal() = default;`) — иначе при удалении объекта производного класса через указатель на базовый класс будет вызван лишь деструктор базового класса, а деструктор производного класса окажется пропущен, что приведёт к утечке ресурсов, выделенных производным классом.
