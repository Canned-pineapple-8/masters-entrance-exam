### 1. Понятие и условие применимости

Двоичным (бинарным) поиском, называемым также методом деления пополам или дихотомией, называется алгоритм поиска заданного значения (ключа) в массиве, применимый лишь при одном принципиальном условии — массив должен быть предварительно отсортирован. Именно упорядоченность элементов массива позволяет на каждом шаге алгоритма однозначно определить, в какой из двух его половин может находиться искомый элемент, полностью отбрасывая другую половину из дальнейшего рассмотрения.

### 2. Идея алгоритма

Алгоритм относится к методам типа «разделяй и властвуй»: искомое значение сравнивается со средним элементом текущего рассматриваемого диапазона массива. Если значения совпадают, поиск завершён успешно. Если искомое значение меньше среднего элемента, дальнейший поиск продолжается в левой половине диапазона (поскольку в силу отсортированности массива искомый элемент, если он вообще присутствует, не может находиться правее среднего); если больше — в правой половине. Процесс повторяется до тех пор, пока элемент не будет найден, либо пока рассматриваемый диапазон не окажется пуст (что означает отсутствие искомого элемента в массиве).

### 3. Итеративная реализация

```c++
int BinarySearch(const std::vector<int>& arr, int key) {
    int low = 0, high = static_cast<int>(arr.size()) - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;   // безопасный от переполнения способ вычисления середины
        if (arr[mid] == key) {
            return mid;
        } else if (arr[mid] < key) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return -1;   // элемент не найден
}
```

### 4. Рекурсивная реализация

```c++
int BinarySearchRecursive(const std::vector<int>& arr, int key, int low, int high) {
    if (low > high) {
        return -1;   // элемент не найден
    }
    int mid = low + (high - low) / 2;
    if (arr[mid] == key) {
        return mid;
    } else if (arr[mid] < key) {
        return BinarySearchRecursive(arr, key, mid + 1, high);
    } else {
        return BinarySearchRecursive(arr, key, low, mid - 1);
    }
}
```

### 5. Корректность алгоритма

Корректность двоичного поиска опирается на инвариант, сохраняющийся на протяжении всей работы алгоритма: если искомый элемент присутствует в исходном массиве, он непременно содержится в текущем рассматриваемом диапазоне $[low, high]$. Инвариант, очевидно, истинен изначально (когда диапазон охватывает весь массив), а каждый шаг алгоритма (сужение диапазона до одной из его половин, гарантированно не содержащей искомый элемент — с учётом отсортированности массива и результата сравнения со средним элементом) сохраняет истинность инварианта. Когда диапазон сужается до единственного элемента либо оказывается пуст, инвариант однозначно определяет исход поиска.

### 6. Анализ трудоёмкости

На каждом шаге алгоритма размер рассматриваемого диапазона сокращается вдвое, что описывается рекуррентным соотношением $T(n) = T(n/2) + O(1)$, решением которого (согласно основной теореме о рекуррентных соотношениях, применяемой при анализе алгоритмов) является $T(n) = O(\log n)$. Трудоёмкость в лучшем случае составляет $O(1)$ (если искомый элемент оказывается точно средним элементом массива уже на первом шаге), а в среднем и в худшем случаях — $O(\log n)$, что кардинально эффективнее линейного поиска ($O(n)$), рассмотренного в одном из предыдущих вопросов, — особенно ощутимо при больших объёмах данных: например, для массива из миллиона элементов двоичный поиск требует не более $\lceil \log_2 10^6 \rceil \approx 20$ сравнений против до миллиона сравнений в худшем случае для линейного поиска.

Существен и оборотный аспект: применение двоичного поиска оправдано лишь тогда, когда массив уже отсортирован (или сортируется однократно для последующего многократного использования), поскольку сама по себе сортировка требует не менее $O(n \log n)$ операций, — если поиск в массиве производится лишь однократно, а массив изначально не отсортирован, суммарные затраты на сортировку с последующим двоичным поиском оказываются не меньше, чем при простом линейном поиске без предварительной сортировки.

### 7. Классическая ошибка реализации: переполнение при вычислении середины

Исторически распространённая ошибка реализации двоичного поиска связана с вычислением индекса среднего элемента диапазона по формуле `mid = (low + high) / 2`: при достаточно больших значениях `low` и `high` их сумма способна превысить максимально допустимое значение используемого целочисленного типа, что приводит к переполнению и, как следствие, к некорректному результату — эта ошибка настолько распространена, что присутствовала даже в эталонном коде, приведённом в ряде авторитетных учебных изданий по программированию. Корректная, устойчивая к переполнению формула вычисления середины диапазона — `mid = low + (high - low) / 2`, — использованная в примерах реализации выше, — вычисляет то же самое значение середины, но без риска промежуточного переполнения суммы `low + high`.

### 8. Модификации алгоритма

Базовая версия двоичного поиска, приведённая выше, находит лишь какое-то одно вхождение искомого значения в массив и не специфицирует, какое именно, если в массиве присутствует несколько равных искомому значению элементов (дубликатов). На практике нередко требуется отыскать конкретно первое либо, соответственно, последнее вхождение искомого значения в отсортированном массиве, — для чего базовый алгоритм модифицируется так, чтобы при обнаружении совпадения со средним элементом поиск не завершался немедленно, а продолжался в соответствующей половине диапазона, сужая границы до тех пор, пока не будет однозначно определена крайняя (первая или последняя) позиция искомого значения. Именно такую функциональность реализуют, в частности, стандартные алгоритмы `std::lower_bound` (отыскивающий первый элемент, не меньший заданного значения) и `std::upper_bound` (отыскивающий первый элемент, строго больший заданного значения) стандартной библиотеки шаблонов, рассмотренной в одном из предыдущих вопросов.

### 9. Ограничения применимости

Двоичный поиск эффективен лишь для структур данных, обеспечивающих доступ к произвольному (в частности, среднему) элементу диапазона за постоянное время, — в первую очередь для массивов и аналогичных им структур с произвольным доступом; для структур, не предоставляющих такого доступа (в частности, для связного списка, к элементам которого возможен лишь последовательный доступ), непосредственное применение двоичного поиска утрачивает свою эффективность, поскольку одно только определение среднего элемента диапазона потребовало бы линейного, а не постоянного времени.
