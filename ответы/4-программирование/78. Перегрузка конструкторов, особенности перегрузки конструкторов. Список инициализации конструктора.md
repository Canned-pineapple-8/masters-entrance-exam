### 1. Понятие перегрузки конструкторов

Подобно любым другим функциям-членам класса, конструкторы могут быть перегружены — класс вправе содержать сразу несколько конструкторов, различающихся числом или типами принимаемых параметров, каждый из которых предлагает собственный, отдельный способ инициализации объекта. Выбор конкретного конструктора, вызываемого при создании объекта, производится компилятором на этапе компиляции по тем же общим правилам разрешения перегрузки, что рассматривались ранее применительно к перегрузке обычных функций.

```c++
class Rectangle {
public:
    Rectangle() : width(1), height(1) {}                    // конструктор по умолчанию
    Rectangle(double side) : width(side), height(side) {}    // конструктор квадрата
    Rectangle(double w, double h) : width(w), height(h) {}   // общий конструктор

private:
    double width, height;
};

Rectangle r1;           // вызовет первый конструктор
Rectangle r2(5);        // вызовет второй конструктор
Rectangle r3(3, 4);     // вызовет третий конструктор
```

### 2. Особенности перегрузки конструкторов

**Автоматическая генерация конструктора по умолчанию.** Существен принципиальный нюанс, отличающий конструкторы от обычных перегруженных функций: если класс не содержит ни одного явно определённого программистом конструктора, компилятор автоматически генерирует для него конструктор по умолчанию (без параметров). Однако как только программист явно определяет хотя бы один конструктор (с любым количеством параметров), автоматическая генерация конструктора по умолчанию прекращается, — и если объект такого класса всё же должен допускать создание без явного указания аргументов, соответствующий конструктор без параметров необходимо объявить явно (либо, начиная с C++11, воспользоваться синтаксисом `Rectangle() = default;`, поручающим генерацию его стандартной реализации самому компилятору).

**Конструктор копирования и конструктор перемещения.** Особую роль среди перегруженных конструкторов занимают конструктор копирования (принимающий параметр типа `const T&`) и, начиная с C++11, конструктор перемещения (принимающий параметр типа `T&&`), рассмотренные в вопросе о конструкторах и деструкторах: компилятор распознаёт их не просто как ещё одну перегруженную версию, а как специальные функции-члены, для которых предусмотрены собственные, отдельные правила автоматической генерации (зависящие, в частности, от того, определил ли программист какие-либо иные специальные функции-члены класса).

**Параметры по умолчанию как альтернатива перегрузке.** Единственный конструктор, часть параметров которого снабжена значениями по умолчанию, во многих случаях способен заменить собой сразу несколько перегруженных конструкторов, сократив дублирование кода:

```c++
class Person {
public:
    Person(std::string name = "Undefined", unsigned age = 18)
        : name(name), age(age) {}
private:
    std::string name;
    unsigned age;
};

Person p1;                  // используются оба значения по умолчанию
Person p2("Tom");           // используется одно значение по умолчанию
Person p3("Tom", 38);       // оба значения указаны явно
```

Существенно, однако, что сочетание параметров по умолчанию с одновременно существующими явно перегруженными конструкторами способно порождать неоднозначность вызова: если для данного набора фактических аргументов сразу несколько конструкторов (либо один конструктор с несколькими вариантами применения параметров по умолчанию) оказываются в равной степени подходящими кандидатами, компилятор не может однозначно выбрать, какой из них вызвать, и сообщает об ошибке компиляции.

**Делегирующие конструкторы.** Начиная со стандарта C++11, одному конструктору класса разрешено вызывать другой конструктор того же класса непосредственно из своего списка инициализации, — этот приём называется делегированием конструкторов и позволяет сосредоточить общую для нескольких перегруженных конструкторов логику инициализации в одном месте, избегая её дублирования:

```c++
class Point {
public:
    Point() : Point(0, 0) {}                    // делегирует конструктору Point(double, double)
    Point(double x, double y) : x(x), y(y) {}
private:
    double x, y;
};
```

При этом действует важное ограничение: конструктор, делегирующий инициализацию другому конструктору, не вправе одновременно указывать в своём собственном списке инициализации какие-либо ещё члены класса — единственным элементом такого списка может быть только сам вызов делегируемого конструктора. Кроме того, синтаксис делегирования не защищает от случайного создания бесконечной рекурсии (когда конструктор A делегирует конструктору B, а тот, в свою очередь, — снова конструктору A); обязанность избегать подобных циклов целиком возлагается на самого программиста, поскольку компилятор такую ошибку не диагностирует вплоть до фактического переполнения стека вызовов во время выполнения программы.
### 3. Список инициализации конструктора

Список инициализации членов класса — синтаксическая конструкция, указываемая после двоеточия, следующего непосредственно за списком параметров конструктора и предшествующая его телу, — уже был кратко упомянут в вопросе о конструкторах и деструкторах; рассмотрим его подробнее применительно к перегруженным конструкторам.

**Необходимость применения.** Для ряда категорий членов класса список инициализации является не просто предпочтительным, а единственно возможным способом их инициализации: константные поля (`const`) и поля ссылочного типа обязаны получить своё значение непосредственно в момент создания объекта и не могут быть впоследствии изменены операцией присваивания в теле конструктора; аналогично, инициализация подобъекта базового класса (при наличии у него лишь параметризованных, но не конструктора по умолчанию) и полей, представляющих собой объекты класса без собственного конструктора по умолчанию, возможна исключительно через список инициализации.

**Порядок инициализации.** Существен принципиальный, часто упускаемый из виду нюанс: фактический порядок инициализации членов класса определяется не порядком их перечисления в самом списке инициализации, а порядком их объявления непосредственно в теле класса. Если порядок в списке инициализации не совпадает с порядком объявления, компилятор, тем не менее, инициализирует члены в порядке их объявления (многие компиляторы при этом выдают предупреждение о таком несоответствии), — соответственно, порядок записи элементов списка инициализации следует по возможности приводить в соответствие порядку объявления самих полей во избежание путаницы, в особенности если инициализация одного поля зависит от значения другого, уже инициализированного поля.

```c++
class Example {
public:
    Example(int a) : y(a), x(y) {}   // порядок в списке: y, затем x
                                       // фактический порядок инициализации: x, затем y
                                       // (поскольку x объявлен раньше y) — y ещё не инициализирован!
private:
    int x;   // объявлен первым
    int y;   // объявлен вторым
};
```

**Эффективность.** Инициализация членов класса типа пользовательского класса через список инициализации выполняется однократным вызовом соответствующего конструктора с нужным значением, тогда как присваивание значения такому полю непосредственно в теле конструктора предполагает две последовательные операции — сперва неявный вызов конструктора по умолчанию для этого поля, а затем отдельную операцию присваивания, — что менее эффективно и, как отмечено выше, попросту невозможно для полей, чей тип не располагает конструктором по умолчанию.
