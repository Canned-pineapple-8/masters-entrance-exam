### 1. Общее понятие массива объектов

Массивом объектов называется массив, каждый элемент которого представляет собой не значение встроенного типа, а полноценный объект пользовательского класса. Объявляется такой массив синтаксически точно так же, как обычный массив элементов встроенного типа, — с той лишь особенностью, что для его создания и инициализации задействуется механизм конструкторов, рассмотренный в предыдущих вопросах.

### 2. Статический массив объектов

**Инициализация конструктором по умолчанию.** Если при объявлении массива объектов не указан явный список инициализации, каждый его элемент по очереди инициализируется конструктором по умолчанию, — соответственно, класс, объекты которого предполагается собирать в подобный неинициализированный массив, обязан располагать доступным конструктором по умолчанию (либо явно определённым, либо неявно сгенерированным компилятором, что, как отмечалось в вопросе о перегрузке конструкторов, происходит лишь при отсутствии у класса каких-либо иных, явно определённых конструкторов).

```c++
class Point {
public:
    Point() : x(0), y(0) {}
    Point(double x, double y) : x(x), y(y) {}
private:
    double x, y;
};

Point points[10];   // все десять элементов инициализируются Point()
```

**Явная инициализация через список инициализации.** Если класс определяет параметризованный конструктор, каждый элемент массива может быть инициализирован явным вызовом конструктора с нужными аргументами, указанным в списке инициализации массива:

```c++
Point points[3] = { Point(1, 2), Point(3, 4), Point(5, 6) };
```

При этом допустима и неполная инициализация: если список инициализации содержит меньше элементов, чем размер массива, оставшиеся, не упомянутые в списке элементы инициализируются конструктором по умолчанию, — что, соответственно, вновь требует его наличия у класса.

### 3. Динамический массив объектов

Динамический массив объектов создаётся оператором `new[]`, возвращающим указатель на первый элемент выделенной в динамической памяти области:

```c++
Point* points = new Point[10];
```

Существен принципиальный нюанс, отличающий динамическое выделение массива объектов от статического: при использовании оператора `new[]` для каждого элемента массива вызывается исключительно конструктор по умолчанию — передать различные аргументы конструктора для отдельных элементов динамического массива, в отличие от статического массива с явным списком инициализации, средствами одного лишь оператора `new[]` невозможно; при необходимости индивидуальной инициализации элементов её приходится выполнять уже после выделения памяти, отдельным циклом, посредством присваивания или вызова соответствующих методов.

**Освобождение динамического массива объектов.** Для освобождения памяти, выделенной оператором `new[]`, обязательно применяется парная ему форма оператора удаления — `delete[]`, а не обычный `delete`:

```c++
delete[] points;
```

Использование обычного `delete` (без квадратных скобок) применительно к указателю, полученному от `new[]`, приводит к неопределённому поведению программы: в частности, оператор `delete[]` гарантированно вызывает деструктор для каждого без исключения элемента массива (что принципиально важно, если деструктор класса освобождает какие-либо собственные, дополнительные ресурсы), тогда как обычный `delete` в лучшем случае вызовет деструктор лишь для первого элемента, оставив остальные объекты массива корректно неразрушенными.

### 4. Обработка массива объектов

Обход и обработка элементов массива объектов производятся теми же средствами, что и для массива значений встроенного типа, — циклом по индексу либо, начиная с C++11, циклом по диапазону (range-based for), — с той разницей, что обращение к каждому элементу позволяет вызывать его методы и обращаться к его полям (через оператор `.` для массива объектов-значений, либо через оператор `->` для массива указателей на объекты, рассматриваемого ниже).

```c++
for (int i = 0; i < 10; ++i) {
    points[i].Print();
}

// либо, эквивалентным образом:
for (const Point& p : points) {
    p.Print();
}
```

### 5. Массив указателей на объекты

Наряду с массивом самих объектов (массивом их значений), нередко применяется массив указателей на объекты, каждый элемент которого хранит не сам объект, а адрес объекта, отдельно размещённого в динамической памяти. Такая организация особенно существенна при работе с полиморфными иерархиями классов, рассмотренными в вопросе о виртуальных функциях: массив указателей на базовый класс, каждый элемент которого фактически указывает на объект того или иного производного класса, позволяет корректно реализовать полиморфную обработку разнородной по фактическому типу коллекции объектов, — тогда как массив объектов-значений базового класса неизбежно приводил бы к уже рассмотренной ранее проблеме обрезки объекта, полностью теряя специфичную для производных классов информацию.

```c++
Shape* shapes[3];
shapes[0] = new Circle(5);
shapes[1] = new Rectangle(3, 4);
shapes[2] = new Circle(2);

for (int i = 0; i < 3; ++i) {
    std::cout << shapes[i]->Area() << "\n";   // корректный полиморфный вызов
}

for (int i = 0; i < 3; ++i) {
    delete shapes[i];   // каждый объект должен быть освобождён по отдельности
}
```

Существенная оборотная сторона такого подхода — необходимость самостоятельного, ручного управления временем жизни каждого динамически выделенного объекта, на который указывает элемент массива: если хотя бы один из них не будет впоследствии явно удалён оператором `delete`, возникает утечка памяти. На практике для устранения этого риска элементы подобного массива указателей всё чаще оформляют не в виде «сырых» указателей, а в виде умных указателей стандартной библиотеки (в частности, `std::unique_ptr`), автоматически обеспечивающих корректное освобождение каждого объекта по мере надобности без явного вызова `delete` программистом.
