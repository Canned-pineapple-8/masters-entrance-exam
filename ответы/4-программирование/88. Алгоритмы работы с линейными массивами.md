### 1. Общая характеристика линейного массива

Линейным (одномерным) массивом называется структура данных, хранящая последовательность однотипных элементов в непрерывной области памяти, доступ к каждому из которых осуществляется по его порядковому номеру (индексу) за постоянное время, не зависящее от размера массива. Именно эта возможность прямого, произвольного доступа по индексу лежит в основе всех рассматриваемых далее алгоритмов обработки линейных массивов.

### 2. Базовые операции обработки массива

**Вычисление агрегатных характеристик.** Нахождение суммы, среднего арифметического, минимального или максимального элемента массива выполняется однократным последовательным проходом по всем его элементам за линейное время $O(n)$, где $n$ — число элементов массива.

```c++
int FindMax(const std::vector<int>& arr) {
    int maxValue = arr[0];
    for (size_t i = 1; i < arr.size(); ++i) {
        if (arr[i] > maxValue) {
            maxValue = arr[i];
        }
    }
    return maxValue;
}
```

**Реверс (обращение порядка) массива.** Выполняется попарным обменом значениями элементов, симметричных относительно середины массива, — элемента с индексом $i$ с элементом с индексом $n-1-i$, — что требует $\lfloor n/2 \rfloor$ обменов и, соответственно, времени $O(n)$.

**Вставка и удаление элемента.** Поскольку элементы линейного массива хранятся в непрерывной области памяти без промежутков, вставка нового элемента в произвольную позицию (либо удаление элемента из произвольной позиции) требует сдвига всех последующих элементов массива на одну позицию вправо (при вставке) или влево (при удалении), что в общем случае занимает время $O(n)$ — в отличие от структур данных, специально предназначенных для эффективной вставки и удаления (например, связного списка).

### 3. Алгоритмы поиска элемента в массиве

**Линейный (последовательный) поиск.** Простейший алгоритм поиска, применимый к произвольному, в том числе неотсортированному массиву: элементы массива последовательно сравниваются с искомым значением, начиная с первого, вплоть до его обнаружения либо до исчерпания всего массива. Трудоёмкость алгоритма в худшем случае составляет $O(n)$.

```c++
int LinearSearch(const std::vector<int>& arr, int key) {
    for (size_t i = 0; i < arr.size(); ++i) {
        if (arr[i] == key) {
            return static_cast<int>(i);
        }
    }
    return -1;   // элемент не найден
}
```

**Бинарный (двоичный) поиск.** Существенно более быстрый алгоритм, применимый, однако, лишь к предварительно отсортированному массиву. Метод основан на принципе «разделяй и властвуй»: искомое значение сравнивается со средним элементом текущего рассматриваемого диапазона массива; если оно совпадает — поиск завершён; если искомое значение меньше среднего элемента, поиск рекурсивно (либо итеративно) продолжается в левой половине диапазона, если больше — в правой; на каждом шаге размер рассматриваемого диапазона сокращается вдвое, что обеспечивает логарифмическую трудоёмкость алгоритма — $O(\log n)$.

```c++
int BinarySearch(const std::vector<int>& arr, int key) {
    int low = 0, high = static_cast<int>(arr.size()) - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] == key) {
            return mid;
        } else if (arr[mid] < key) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return -1;   // элемент не найден
}
```

### 4. Алгоритмы сортировки массива

**Сортировка пузырьком (bubble sort).** Простейший, но наименее эффективный из широко известных алгоритмов сортировки: массив многократно просматривается слева направо, и каждая пара соседних элементов, нарушающая требуемый порядок, меняется местами; после каждого такого прохода наибольший из ещё не отсортированных элементов гарантированно «всплывает» на своё окончательное место в конце массива. Трудоёмкость алгоритма составляет $O(n^2)$ как в среднем, так и в худшем случае.

```c++
void BubbleSort(std::vector<int>& arr) {
    size_t n = arr.size();
    for (size_t i = 0; i < n - 1; ++i) {
        for (size_t j = 0; j < n - 1 - i; ++j) {
            if (arr[j] > arr[j + 1]) {
                std::swap(arr[j], arr[j + 1]);
            }
        }
    }
}
```

**Сортировка выбором (selection sort).** На каждом из $n$ шагов алгоритм отыскивает минимальный (либо максимальный) элемент среди ещё не отсортированной части массива и переставляет его на очередную, окончательную позицию в отсортированной части. Трудоёмкость также составляет $O(n^2)$, однако, в отличие от пузырьковой сортировки, число фактических перестановок элементов у сортировки выбором минимально — не более $n-1$.

**Сортировка вставками (insertion sort).** Массив мысленно делится на уже отсортированную (изначально — из одного первого элемента) и ещё не обработанную части; на каждом шаге очередной элемент из необработанной части «вставляется» на подходящую по порядку позицию внутри уже отсортированной части, для чего требуется сдвинуть на одну позицию вправо все элементы отсортированной части, большие вставляемого значения. Трудоёмкость в худшем случае также составляет $O(n^2)$, однако на практике сортировка вставками особенно эффективна для уже почти отсортированных массивов, приближаясь на них к линейной трудоёмкости.

**Сортировка слиянием (merge sort).** Алгоритм типа «разделяй и властвуй»: массив рекурсивно делится пополам вплоть до тривиальных подмассивов из одного элемента, после чего соседние отсортированные подмассивы последовательно попарно сливаются в единый отсортированный массив большего размера. Трудоёмкость алгоритма гарантированно составляет $O(n \log n)$ независимо от исходного порядка элементов, а сама сортировка является устойчивой (сохраняет относительный порядок равных по значению элементов), ценой дополнительных затрат памяти порядка $O(n)$, требуемых для промежуточного хранения при слиянии.

**Быстрая сортировка (quicksort).** Также алгоритм типа «разделяй и властвуй»: среди элементов массива выбирается некоторый опорный элемент (пивот), после чего массив разбивается (партиционируется) на две части — элементы, меньшие опорного, и элементы, не меньшие его, — и та же процедура рекурсивно применяется к каждой из полученных частей по отдельности. В среднем случае трудоёмкость быстрой сортировки составляет $O(n \log n)$, что делает её одним из наиболее эффективных на практике алгоритмов сортировки, однако при неудачном выборе опорного элемента (в частности, на уже отсортированном или специально подобранном массиве) трудоёмкость в худшем случае может деградировать до $O(n^2)$.

### 5. Сводное замечание

Выбор конкретного алгоритма поиска или сортировки для линейного массива на практике определяется совокупностью факторов: размером массива, требованием к устойчивости сортировки, доступным объёмом дополнительной памяти, а также тем, отсортирован ли массив заранее (что оправдывает применение существенно более быстрого бинарного поиска вместо линейного) и насколько часто предполагается его последующее изменение (поскольку вставка и удаление элементов линейного массива, как отмечалось выше, в общем случае требуют сдвига остальных элементов и потому сравнительно затратны).
