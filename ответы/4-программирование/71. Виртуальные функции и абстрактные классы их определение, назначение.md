### 1. Виртуальные функции

Виртуальной функцией называется функция-член класса, объявленная с ключевым словом `virtual`, для которой при обращении к объекту через указатель или ссылку на базовый класс конкретная вызываемая реализация определяется не статическим (объявленным) типом указателя или ссылки, а фактическим типом объекта, на который они указывают, — причём это определение производится уже во время выполнения программы (динамическое связывание, рассмотренное в вопросе о полиморфизме). Виртуальные функции составляют технический механизм, посредством которого в C++ реализуется динамический (рантайм) полиморфизм.

```c++
class Shape {
public:
    virtual double Area() const {
        return 0.0;
    }
};

class Circle : public Shape {
public:
    Circle(double radius) : radius(radius) {}
    double Area() const override {
        return 3.14159 * radius * radius;
    }
private:
    double radius;
};
```

Здесь ключевое слово `override`, введённое стандартом C++11, необязательно с точки зрения синтаксиса, но настоятельно рекомендуется к использованию при переопределении виртуальной функции в производном классе: оно явным образом сообщает компилятору о намерении переопределить именно виртуальную функцию базового класса, что позволяет компилятору выявить ошибку, если сигнатура функции в производном классе фактически не совпадает с сигнатурой соответствующей виртуальной функции базового класса (в этом случае вместо переопределения произошло бы случайное создание новой, независимой функции, скрывающей — но не переопределяющей — функцию базового класса). Существен также следующий нюанс: единожды объявленная виртуальной в базовом классе, функция остаётся виртуальной во всех последующих производных классах иерархии, даже если ключевое слово `virtual` не повторяется явно при её переопределении. Дополнительное ключевое слово `final`, также введённое в C++11, применяется к виртуальной функции для запрета её дальнейшего переопределения в классах, производных от текущего.

### 2. Чисто виртуальные функции

Чисто виртуальной (абстрактной) функцией называется виртуальная функция, объявленная в базовом классе без содержательной реализации (тела), — вместо тела функции её объявление завершается специальным синтаксисом `= 0`:

```c++
virtual double Area() const = 0;
```

Назначение чисто виртуальной функции состоит в том, чтобы определить сам факт наличия у класса некоторой функции (её сигнатуру, то есть контракт, обязательный для реализации), не предоставляя при этом никакой реализации по умолчанию — реализация всецело возлагается на производные классы. Существен формальный нюанс: чисто виртуальная функция, вопреки распространённому заблуждению, при желании может иметь и собственное тело (реализацию), однако вызвать такую реализацию можно исключительно посредством явного полностью квалифицированного имени (например, `Shape::Area()`), но никак не через обычный полиморфный вызов, — на практике эта возможность применяется довольно редко.

### 3. Абстрактные классы

Абстрактным называется класс, который содержит хотя бы одну чисто виртуальную функцию (либо наследует таковую от базового класса, не переопределив её собственной реализацией). Ключевое свойство абстрактного класса состоит в том, что для него невозможно создать (инстанцировать) ни одного объекта напрямую — компилятор отклонит попытку такого объявления с ошибкой компиляции, — поскольку у класса отсутствует полная, содержательная реализация хотя бы одной из его функций.

```c++
class Shape {
public:
    virtual double Area() const = 0;   // чисто виртуальная функция
    virtual ~Shape() = default;
};

// Shape s; // ошибка компиляции: Shape - абстрактный класс

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : width(w), height(h) {}
    double Area() const override { return width * height; }
private:
    double width, height;
};
```

При этом абстрактный класс, несмотря на невозможность его непосредственного инстанцирования, вполне может служить типом указателя или ссылки, что и обеспечивает возможность полиморфной работы с объектами всех производных, уже конкретных (неабстрактных) классов через единый, общий для них тип базового класса:

```c++
Shape* shapes[] = { new Rectangle(3, 4), new Circle(2) };
for (Shape* s : shapes) {
    std::cout << s->Area() << "\n";
}
```

Существен также следующий момент: если производный класс не переопределяет все без исключения унаследованные им чисто виртуальные функции, он сам по-прежнему остаётся абстрактным (то есть объекты такого класса также невозможно создать напрямую), — статус «конкретного», полностью реализованного класса производный класс приобретает лишь тогда, когда содержательно реализует все чисто виртуальные функции, унаследованные им по всей цепочке наследования.
### 4. Назначение: определение общего интерфейса

Абстрактный класс, назначение которого исчерпывается лишь определением набора чисто виртуальных функций (без каких-либо полей и без реализованных обычных методов), фактически играет роль интерфейса — контракта, специфицирующего, какой набор операций обязан поддерживать всякий класс, желающий этому интерфейсу соответствовать, без навязывания какой-либо конкретной реализации этих операций. В отличие от таких языков, как Java или C#, C++ не располагает отдельным синтаксическим ключевым словом `interface`: роль интерфейса в C++ традиционно исполняет именно такой «чисто абстрактный» класс, состоящий исключительно из чисто виртуальных функций (и, как правило, виртуального деструктора).

### 5. Чисто виртуальный деструктор

Отдельного упоминания заслуживает особый случай — чисто виртуальный деструктор (`virtual ~Base() = 0;`). В отличие от прочих чисто виртуальных функций, деструктор, объявленный чисто виртуальным, тем не менее обязан иметь собственное тело (реализацию, пусть даже пустую), поскольку деструкторы всех классов иерархии неизбежно вызываются при уничтожении объекта (в порядке, рассмотренном в предыдущем вопросе), включая деструктор самого базового класса, — а вызов функции без какой бы то ни было реализации невозможен в принципе. Приём с объявлением чисто виртуального деструктора применяется в тех случаях, когда требуется сделать класс абстрактным (запретить создание его самостоятельных объектов), но при этом среди его функций не находится иного, содержательно подходящего кандидата на роль чисто виртуальной функции, — деструктор, будучи обязательным элементом любого класса, оказывается удобным техническим средством для этой цели.
