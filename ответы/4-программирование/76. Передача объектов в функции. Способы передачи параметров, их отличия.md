### 1. Общее понятие способов передачи параметров

При вызове функции её формальные параметры могут быть связаны с фактически переданными аргументами одним из нескольких принципиально различающихся способов, определяющих, во-первых, происходит ли при вызове копирование передаваемых данных, и во-вторых, способна ли функция изменить состояние переданного ей объекта, видимое впоследствии вызывающему коду. В языке C++ различают передачу параметров по значению, по ссылке и по указателю, а начиная со стандарта C++11 — также и по rvalue-ссылке.
### 2. Передача по значению

При передаче по значению для параметра функции создаётся полноценная, независимая копия фактически переданного аргумента (для объекта пользовательского класса это означает вызов его конструктора копирования); функция оперирует исключительно этой копией, и любые изменения, произведённые ею над параметром, никак не отражаются на исходном объекте (переменной), использованном при вызове.

```c++
void Increment(int x) {
    ++x;   // изменяется только локальная копия
}

int n = 10;
Increment(n);
// n по-прежнему равно 10
```

Существенный недостаток передачи по значению применительно к объектам классов и крупным структурам данных состоит в стоимости самого копирования: чем больше объём и сложнее внутреннее устройство объекта (а значит, и логика его конструктора копирования), тем более затратной в отношении времени и памяти оказывается каждая передача такого объекта по значению.

Отдельного упоминания заслуживает так называемая проблема обрезки объекта (object slicing), возникающая при передаче по значению в контексте наследования и полиморфизма: если объект производного класса передаётся по значению параметру, объявленному типом базового класса, копируется лишь та часть объекта, что относится к базовому классу, — все данные, специфичные для производного класса, оказываются буквально «обрезаны» (утеряны), а вызовы виртуальных функций для такого параметра будут разрешаться в соответствии с базовым, а не исходным производным типом, поскольку копия внутри функции фактически является полноценным, самостоятельным объектом именно базового класса, а не производного.

```c++
void Print(Base obj) {   // параметр передан ПО ЗНАЧЕНИЮ
    obj.Speak();          // всегда вызовет Base::Speak(), даже если передан Derived
}
```

### 3. Передача по ссылке

При передаче по ссылке параметр функции связывается непосредственно с исходным объектом (переменной), использованным при вызове, — никакого копирования при этом не производится, а любое изменение, выполненное функцией над параметром, отражается на самом исходном объекте.

```c++
void Increment(int& x) {
    ++x;
}

int n = 10;
Increment(n);
// n теперь равно 11
```

Передача по ссылке существенно эффективнее передачи по значению применительно к объектам классов и крупным структурам, поскольку исключает затраты на копирование. Наиболее распространённый на практике вариант — передача по константной ссылке (`const T&`): подобно передаче по значению, она гарантирует, что функция не изменит переданный ей объект, но при этом, в отличие от передачи по значению, не требует затратного копирования и, что немаловажно, не подвержена проблеме обрезки объекта (поскольку ссылка связывается с фактическим, динамическим типом переданного объекта, и виртуальные функции для такого параметра разрешаются корректно, с учётом истинного типа объекта).

```c++
void Print(const Base& obj) {   // параметр передан ПО КОНСТАНТНОЙ ССЫЛКЕ
    obj.Speak();                 // корректно разрешится в Derived::Speak(), если передан Derived
}
```

Передача по неконстантной ссылке (`T&`), в свою очередь, применяется, когда функция должна иметь возможность изменить переданный ей объект (в том числе, в частности, для реализации возврата сразу нескольких результатов через параметры-результаты). Недостаток этого способа — то, что из самого текста вызова функции (в отличие от передачи по указателю, рассматриваемой ниже) не всегда очевидно, способна ли функция изменить переданный ей аргумент, поскольку синтаксис вызова функции с параметром-ссылкой ничем не отличается от вызова с параметром, передаваемым по значению.

### 4. Передача по указателю

При передаче по указателю функции передаётся адрес исходного объекта, который она обязана явно разыменовывать (`*ptr` или `ptr->member`) для доступа к самому объекту. По достигаемому эффекту (отсутствие копирования, возможность изменения исходного объекта функцией) передача по указателю во многом схожа с передачей по неконстантной ссылке, однако обладает рядом отличий.

```c++
void Increment(int* x) {
    if (x != nullptr) {
        ++(*x);
    }
}

int n = 10;
Increment(&n);
// n теперь равно 11
```

Во-первых, указатель, в отличие от ссылки, может принимать специальное значение `nullptr`, обозначающее отсутствие связанного объекта, — это позволяет реализовать содержательно необязательные параметры функции, у которых сам факт передачи корректного адреса становится дополнительным управляющим признаком. Во-вторых, в отличие от ссылки, которая жёстко связывается с конкретным объектом уже в момент своей инициализации и не может быть впоследствии переприсвоена другому объекту, указатель допускает переприсваивание — внутри функции его можно перенаправить на совершенно другой объект в памяти, не затрагивая исходный. В-третьих, необходимость явно указывать оператор взятия адреса (`&n`) при вызове функции, принимающей параметр по указателю, делает саму возможность изменения переданного аргумента более наглядной непосредственно в месте вызова, по сравнению с передачей по неконстантной ссылке.

### 5. Передача по rvalue-ссылке (перемещение)

Начиная со стандарта C++11, для параметров функции дополнительно введена возможность передачи по rvalue-ссылке (`T&&`), связывающейся исключительно с временными объектами (rvalue-значениями) — например, с результатом, непосредственно возвращаемым другой функцией, или с объектом, явно приведённым к rvalue-ссылке посредством `std::move`. Такая передача лежит в основе семантики перемещения: вместо затратного глубокого копирования внутренних ресурсов временного объекта (который в любом случае будет уничтожен сразу после вызова) функция получает возможность просто «забрать» («украсть») эти ресурсы у временного объекта, оставив его в неопределённом, но корректно разрушаемом состоянии, — что существенно повышает эффективность работы с объектами, владеющими динамически выделяемыми ресурсами.

### 6. Сравнение и практические рекомендации

| Способ передачи | Копирование | Изменение исходного объекта | Типичное применение |
|---|---|---|---|
| По значению | да | нет | небольшие, дешёвые в копировании типы (встроенные типы, малые структуры) |
| По константной ссылке (`const T&`) | нет | нет (гарантировано) | объекты классов и крупные структуры, передаваемые лишь для чтения |
| По неконстантной ссылке (`T&`) | нет | да | параметры-результаты, объекты, которые функция обязана изменить |
| По указателю (`T*`) | нет | да (при ненулевом указателе) | необязательные параметры, случаи, требующие переприсваивания адреса |
| По rvalue-ссылке (`T&&`) | нет (перемещение) | ресурсы временного объекта передаются функции | эффективная передача заведомо временных объектов |

Общее практическое правило таково: для фундаментальных (встроенных) типов данных небольшого размера (`int`, `double`, указатели) передача по значению, как правило, не менее эффективна, чем передача по ссылке, и потому предпочтительна ввиду большей простоты и отсутствия побочных эффектов; для объектов классов и структур, размер или стоимость копирования которых значительны, предпочтительна передача по константной ссылке, если функции не требуется изменять переданный объект, либо по неконстантной ссылке или указателю — если требуется.
