### 1. Общее понятие потока

В библиотеке ввода-вывода C++ (`<iostream>`, `<fstream>`) поток (stream) представляет собой абстракцию последовательной передачи данных между программой и некоторым источником или приёмником — консолью, файлом, строкой в памяти. Для работы с файлами применяются производные от базовых потоковых классов классы `ifstream` (поток чтения из файла, производный от `istream`), `ofstream` (поток записи в файл, производный от `ostream`) и `fstream` (двунаправленный поток чтения и записи, производный от `iostream`). Любой такой поток, в зависимости от указанного при его открытии режима, может интерпретировать передаваемые данные одним из двух принципиально различных способов — как текстовый либо как бинарный поток.

При открытии файлового потока режим задаётся комбинацией флагов (объединяемых оператором `|`): `ios::in` (чтение), `ios::out` (запись, с удалением прежнего содержимого файла), `ios::app` (дозапись в конец файла без удаления прежнего содержимого), `ios::ate` (после открытия сразу переместить указатель в конец файла), `ios::trunc` (усечение файла при открытии) и, что существенно для настоящего вопроса, `ios::binary` — флаг, переводящий поток из текстового режима (используемого по умолчанию, если этот флаг не указан) в бинарный.

```c++
std::ofstream textOut("data.txt");                        // текстовый режим (по умолчанию)
std::ofstream binOut("data.bin", std::ios::binary);        // бинарный режим
```

### 2. Организация текстового потока

Текстовый поток предназначен для передачи данных в виде, предполагающем их дальнейшее восприятие человеком (или интерпретацию иными текстовыми средствами). Запись и чтение в текстовом режиме, как правило, выполняются посредством операторов `<<` и `>>` (форматированный ввод-вывод), которые автоматически выполняют преобразование между внутренним, машинным представлением значения (например, целого числа `int` в его двоичном представлении в памяти) и его текстовым, символьным представлением (последовательностью ASCII-символов, изображающих десятичную запись этого числа), — и обратно, при чтении.

```c++
int value = 12345;
std::ofstream out("data.txt");
out << value;   // в файл записывается текст "12345" (пять символов)
```

Существенная дополнительная особенность текстового режима — платформенно-зависимое преобразование символа перевода строки: символ `'\n'`, записываемый программой, при работе в текстовом режиме на некоторых операционных системах (в частности, на Windows) автоматически преобразуется в характерную для этой платформы последовательность байт, обозначающую конец строки (пару символов возврата каретки и перевода строки, `"\r\n"`), а при последующем чтении в текстовом режиме выполняется обратное преобразование этой последовательности снова в единственный символ `'\n'`.

### 3. Организация бинарного потока

Бинарный поток, открываемый с флагом `ios::binary`, передаёт данные без какого-либо текстового форматирования или интерпретации: содержимое файла в этом случае представляет собой точную, побайтовую копию внутреннего, машинного представления записываемых данных в оперативной памяти. Никакого преобразования символа `'\n'` в бинарном режиме также не производится — все байты передаются между программой и файлом строго без изменений.

Для чтения и записи данных в бинарном режиме, как правило, применяются не форматированные операторы `<<`/`>>`, а специальные методы `write` и `read`, оперирующие непосредственно буфером байт:

```c++
int value = 12345;
std::ofstream out("data.bin", std::ios::binary);
out.write(reinterpret_cast<const char*>(&value), sizeof(value));
// в файл записываются ровно sizeof(int) байт — точное двоичное представление числа 12345
```

```c++
int value;
std::ifstream in("data.bin", std::ios::binary);
in.read(reinterpret_cast<char*>(&value), sizeof(value));
// value восстанавливается из тех же sizeof(int) байт файла
```

Поскольку методы `write` и `read` объявлены оперирующими указателем типа `char*`, а записываемая (считываемая) переменная, как правило, имеет иной тип, требуется явное приведение адреса этой переменной к типу `const char*` (при записи) или `char*` (при чтении) посредством `reinterpret_cast`, — что интерпретирует область памяти переменной просто как последовательность байт, без учёта её содержательного типа.

### 4. Основные отличия при чтении и записи данных

**Способ передачи данных.** В текстовом режиме данные передаются как отформатированный, читаемый человеком текст (посредством `<<`/`>>`, автоматически выполняющих преобразование между машинным и текстовым представлением); в бинарном режиме данные передаются как точная, неизменённая копия их машинного (двоичного) представления в памяти (посредством `write`/`read`, не выполняющих никакого преобразования формата).

**Преобразование символа перевода строки.** Текстовый режим на платформах с иным, чем `'\n'`, представлением конца строки (в частности, на Windows) выполняет автоматическое двустороннее преобразование этого символа при записи и чтении; бинарный режим передаёт байт `'\n'` (как и любой другой байт) без каких-либо изменений.

**Компактность и читаемость.** Текстовое представление данных, как правило, менее компактно (десятичная запись многозначного числа занимает больше байт, чем его внутреннее двоичное представление), но зато непосредственно читаемо и редактируемо человеком в обычном текстовом редакторе, а также, при определённых условиях, переносимо между системами с разным внутренним представлением чисел. Бинарное представление, напротив, компактнее и быстрее в обработке (поскольку не требует преобразования формата при каждой операции чтения или записи), однако нечитаемо непосредственно человеком и, строго говоря, не гарантированно переносимо между системами с различным порядком байт (endianness) или размером базовых типов данных.

**Точность представления вещественных чисел.** При записи вещественного числа в текстовом режиме происходит его преобразование в десятичную текстовую запись с ограниченной точностью (определяемой текущими настройками форматирования потока), что при последующем обратном чтении способно привести к незначительной потере точности по сравнению с исходным значением; в бинарном режиме, напротив, записывается и считывается точное, неизменённое двоичное представление числа, полностью исключающее подобную потерю точности.

Выбор между текстовым и бинарным режимом работы с потоком на практике определяется назначением сохраняемых данных: текстовый режим предпочтителен для файлов, предполагающих чтение или редактирование человеком (конфигурационных файлов, текстовых документов, файлов логов), тогда как бинарный режим предпочтителен для эффективного, точного и компактного сохранения структурированных программных данных, не предназначенных для непосредственного восприятия человеком.
