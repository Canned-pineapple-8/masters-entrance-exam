### 1. Общее понятие функций преобразования типа

При работе с пользовательскими классами нередко возникает необходимость определить правило преобразования объекта этого класса в значение другого типа, либо, наоборот, правило построения объекта класса из значения другого типа. В языке C++ для этой цели предусмотрено два самостоятельных механизма, действующих в противоположных направлениях: конвертирующий конструктор, определяющий преобразование извне в тип класса, и оператор преобразования типа, определяющий преобразование из типа класса вовне.

### 2. Конвертирующие конструкторы

Конструктор класса, принимающий единственный параметр (либо, начиная со стандарта C++11, конструктор, у которого все параметры, кроме одного, снабжены значениями по умолчанию), одновременно с ролью обычного конструктора неявно определяет и правило преобразования значения типа этого параметра в тип самого класса; такой конструктор называется конвертирующим.

```c++
class Fraction {
public:
    Fraction(int numerator, int denominator = 1)
        : numerator(numerator), denominator(denominator) {}
private:
    int numerator, denominator;
};

void PrintFraction(const Fraction& f);

PrintFraction(5);   // целое число 5 неявно преобразуется в Fraction(5, 1)
```

Существен связанный с конвертирующими конструкторами практический риск: компилятор может неявно применить такой конструктор в ситуациях, не предполагавшихся разработчиком класса, приводя к неожиданному, зачастую нежелательному поведению программы. Чтобы запретить неявное применение конструктора для целей преобразования, оставив за ним лишь возможность прямой инициализации объекта или явного приведения типа, конструктор снабжается ключевым словом `explicit`:

```c++
class Fraction {
public:
    explicit Fraction(int numerator, int denominator = 1)
        : numerator(numerator), denominator(denominator) {}
private:
    int numerator, denominator;
};

PrintFraction(5);              // ошибка компиляции: неявное преобразование запрещено
PrintFraction(Fraction(5));    // корректно: явное построение объекта
```

### 3. Операторы преобразования типа

Для определения обратного правила — преобразования объекта класса в значение другого (в том числе встроенного) типа — используется специальная функция-член класса, называемая оператором преобразования типа. Такая функция именуется ключевым словом `operator`, за которым непосредственно следует имя целевого типа преобразования; в отличие от обычных методов, оператор преобразования не указывает возвращаемый тип явно (поскольку он совпадает с типом, названным в имени самого оператора) и не принимает параметров.

```c++
class Counter {
public:
    Counter(int value) : value(value) {}

    operator int() const {
        return value;
    }

private:
    int value;
};

Counter counter(25);
int n = counter;   // неявное преобразование Counter в int посредством operator int()
```

Подобно конвертирующим конструкторам, операторы преобразования типа также могут быть объявлены с ключевым словом `explicit` (начиная с C++11), что запрещает их неявное срабатывание, оставляя возможность преобразования лишь при явном приведении типа (например, посредством `static_cast`):

```c++
class Counter {
public:
    Counter(int value) : value(value) {}
    explicit operator int() const { return value; }
private:
    int value;
};

Counter counter(25);
int n = counter;                       // ошибка компиляции
int m = static_cast<int>(counter);     // корректно: явное приведение
```

### 4. Совместный пример: преобразования в обоих направлениях

```c++
class Money {
public:
    explicit Money(double amount) : amount(amount) {}   // конвертирующий конструктор

    explicit operator double() const {                  // оператор преобразования типа
        return amount;
    }

private:
    double amount;
};

void DisplayBalance(Money m);

DisplayBalance(Money(79.99));                 // прямая инициализация — корректно
DisplayBalance(static_cast<Money>(79.99));    // явное приведение double к Money — корректно
// DisplayBalance(79.99);                     // ошибка: неявное преобразование запрещено explicit

Money balance(150.0);
double d = static_cast<double>(balance);      // явное приведение Money к double — корректно
// double d2 = balance;                       // ошибка: неявное преобразование запрещено explicit
```

В данном примере класс `Money` определяет оба направления преобразования — конвертирующий конструктор `Money(double)`, позволяющий строить объект `Money` из значения типа `double`, и оператор преобразования `operator double()`, позволяющий, в обратную сторону, получить из объекта `Money` значение типа `double`, — при этом оба помечены ключевым словом `explicit`, что вынуждает выполнять оба преобразования лишь явно, устраняя риск случайного, неочевидного неявного преобразования типов в местах программы, где это не было осознанно предусмотрено разработчиком.

### 5. Общая рекомендация

Поскольку неконтролируемые неявные преобразования типов способны приводить к трудно диагностируемым логическим ошибкам (в частности, классический пример — конвертирующий конструктор, принимающий тип `int`, способен неожиданно «подхватить» значение типа `char`, поскольку `char` неявно приводится к `int` по правилам самого языка, что приводит к вызову совершенно не того преобразования, которое подразумевалось), на практике конвертирующие конструкторы и операторы преобразования типа рекомендуется по умолчанию объявлять с ключевым словом `explicit`, разрешая неявное преобразование лишь в тех отдельных, осознанно предусмотренных случаях, когда оно действительно семантически безопасно и удобно для пользователя класса.
