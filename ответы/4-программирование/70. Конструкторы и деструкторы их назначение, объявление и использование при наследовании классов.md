### 1. Назначение конструктора

Конструктором называется специальный метод класса, автоматически вызываемый при создании объекта этого класса и предназначенный для инициализации его внутреннего состояния — присвоения начальных значений полям объекта, а также, при необходимости, для выделения ресурсов (динамической памяти, файловых дескрипторов и тому подобного), которыми объект будет пользоваться на протяжении своего существования. Конструктор имеет то же имя, что и сам класс, не имеет возвращаемого значения (даже `void`) и может быть перегружен — то есть класс может содержать несколько конструкторов с различными наборами параметров.

Среди конструкторов принято выделять несколько содержательно значимых разновидностей: конструктор по умолчанию (конструктор без параметров либо конструктор, все параметры которого имеют значения по умолчанию), параметризованный конструктор (принимающий один или несколько параметров, посредством которых явно задаются начальные значения полей создаваемого объекта), конструктор копирования (принимающий константную ссылку на объект того же класса и инициализирующий новый объект как копию переданного) и, начиная со стандарта C++11, конструктор перемещения (принимающий rvalue-ссылку на временный объект того же класса и «перемещающий» его ресурсы во вновь создаваемый объект без затратного копирования).

```c++
class Point {
public:
    Point() : x(0), y(0) {}                     // конструктор по умолчанию
    Point(double x, double y) : x(x), y(y) {}    // параметризованный конструктор
    Point(const Point& other) : x(other.x), y(other.y) {}  // конструктор копирования

private:
    double x, y;
};
```

### 2. Список инициализации членов

Инициализация полей класса, в особенности полей, объявленных с модификатором `const`, полей ссылочного типа, а также подобъектов базовых классов (рассматриваемых ниже), должна выполняться посредством списка инициализации членов — конструкции, указываемой после двоеточия, следующего за списком параметров конструктора, и предшествующей телу конструктора (как показано в примере класса `Point` выше). Присваивание значений полям непосредственно в теле конструктора (в отличие от списка инициализации) представляет собой не первоначальную инициализацию, а последующее изменение уже инициализированных (пусть и значениями по умолчанию) полей, что для полей типа `const` и ссылочного типа попросту недопустимо, а для прочих полей менее эффективно.

### 3. Назначение деструктора

Деструктором называется специальный метод класса, автоматически вызываемый при уничтожении объекта — по выходе объекта, размещённого в автоматической (стековой) памяти, из области видимости, либо при явном удалении объекта, размещённого в динамической памяти, оператором `delete`. Назначение деструктора — корректное освобождение ресурсов, приобретённых объектом за время его существования (в частности, ранее выделенной динамической памяти, открытых файлов, сетевых соединений и тому подобного), предотвращающее их утечку.

Деструктор именуется по имени класса с предшествующим символом `~`, не принимает параметров, не возвращает значения и не может быть перегружен — класс может иметь не более одного деструктора.

```c++
class Buffer {
public:
    Buffer(size_t size) : data(new int[size]) {}
    ~Buffer() { delete[] data; }

private:
    int* data;
};
```

### 4. Конструкторы и деструкторы при наследовании

**Порядок вызова конструкторов.** Поскольку объект производного класса физически включает в себя подобъект базового класса, при создании объекта производного класса первым непременно выполняется конструктор базового класса, и лишь по его завершении — конструктор самого производного класса (точнее, та часть его тела и список инициализации, что относится непосредственно к собственным членам производного класса). Если конструктор производного класса не указывает явно, какой именно конструктор базового класса следует вызвать, автоматически вызывается конструктор базового класса по умолчанию; если же базовый класс не имеет конструктора по умолчанию (обладая лишь параметризованными конструкторами), конструктор производного класса обязан явно указать вызов одного из них в собственном списке инициализации:

```c++
class Person {
public:
    Person(const std::string& name) : name(name) {}
protected:
    std::string name;
};

class Employee : public Person {
public:
    Employee(const std::string& name, int age)
        : Person(name), age(age) {}   // явный вызов конструктора базового класса

private:
    int age;
};
```

При многоуровневой иерархии наследования конструкторы выполняются последовательно в порядке наследования — от самого базового (корневого) класса к самому производному.

**Порядок вызова деструкторов.** Деструкторы, напротив, выполняются в порядке, строго обратном порядку выполнения конструкторов: при уничтожении объекта производного класса сначала выполняется деструктор самого производного класса, и лишь по его завершении — деструктор базового класса (а при многоуровневой иерархии — далее, вверх по цепочке наследования, вплоть до самого базового класса). Такой порядок логически оправдан: производный класс, как правило, зависит от полностью инициализированного состояния своего базового подобъекта на всём протяжении своего существования, включая момент собственного разрушения, — поэтому базовый подобъект обязан оставаться в корректном состоянии вплоть до завершения работы деструктора производного класса, и лишь после этого может быть разрушен сам.

**Ненаследуемость деструктора.** Существен формальный нюанс: производный класс не наследует деструктор базового класса как таковой (в том смысле, что у каждого класса иерархии — собственный, отдельный деструктор, вызываемый по указанному выше правилу автоматически, а не «доставшийся по наследству» единый деструктор), однако деструктор производного класса, будь он объявлен явно или сгенерирован компилятором неявно, всегда автоматически вызывает деструктор своего базового класса по завершении собственного тела, — поэтому любое освобождение ресурсов, предусмотренное деструктором базового класса, в любом случае будет выполнено при уничтожении объекта производного класса.

**Виртуальный деструктор.** Как отмечалось в вопросе о полиморфизме, если предполагается полиморфное использование иерархии классов (в частности, удаление объекта производного класса через указатель на базовый класс), деструктор базового класса необходимо объявить виртуальным (`virtual ~Base()`); в противном случае вызов `delete` через указатель на базовый класс приведёт к вызову лишь деструктора базового класса, минуя деструктор фактического (производного) типа объекта, что оставит ресурсы, приобретённые производным классом, неосвобождёнными.

**Пример, иллюстрирующий полный порядок вызовов:**

```c++
class Base {
public:
    Base()  { std::cout << "Base создан\n"; }
    ~Base() { std::cout << "Base уничтожен\n"; }
};

class Derived : public Base {
public:
    Derived()  { std::cout << "Derived создан\n"; }
    ~Derived() { std::cout << "Derived уничтожен\n"; }
};

int main() {
    Derived d;
}
```

Результат выполнения приведённой программы:

```
Base создан
Derived создан
Derived уничтожен
Base уничтожен
```

— что в точности отражает описанное выше правило: конструкторы выполняются от базового класса к производному, а деструкторы — в обратном порядке, от производного класса к базовому.
