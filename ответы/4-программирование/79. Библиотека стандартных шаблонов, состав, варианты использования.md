### 1. Общее понятие STL

Стандартной библиотекой шаблонов (STL, Standard Template Library) называется входящая в состав стандартной библиотеки языка C++ совокупность согласованных между собой обобщённых (шаблонных) классов и функций, реализующих наиболее востребованные структуры данных и алгоритмы их обработки. Исторически STL была разработана как самостоятельная библиотека (первоначально фирмой HP, затем SGI) и лишь впоследствии включена в официальный стандарт языка C++. Поскольку все составляющие STL построены на основе шаблонов, рассмотренных в одном из предыдущих вопросов, они применимы практически к любому типу данных, удовлетворяющему определённым, документированным требованиям (например, требованию сравнимости элементов для алгоритма сортировки).

### 2. Состав STL

Ядро STL образуют три взаимосвязанных компонента — контейнеры, итераторы и алгоритмы, — дополняемые функциональными объектами, адаптерами и аллокаторами.

**Контейнеры.** Объекты, предназначенные для хранения набора элементов и управления ими. Контейнеры STL делятся на несколько категорий.

Последовательные контейнеры (`vector`, `list`, `deque`, `array`, `forward_list`) хранят элементы в линейном порядке, определяемом порядком их добавления, и предоставляют доступ к ним по позиции.

Ассоциативные контейнеры (`set`, `map`, `multiset`, `multimap`) автоматически поддерживают элементы в упорядоченном (как правило, по значению ключа) состоянии, реализуемом посредством сбалансированного дерева, и обеспечивают эффективный (логарифмический по времени) поиск элемента по ключу; `map` и `multimap` при этом хранят пары «ключ — значение», тогда как `set` и `multiset` хранят лишь сами ключи.

Неупорядоченные ассоциативные контейнеры (`unordered_set`, `unordered_map`, `unordered_multiset`, `unordered_multimap`), введённые в стандарте C++11, реализованы на основе хеш-таблицы и обеспечивают в среднем ещё более быстрый (константный по времени) поиск элемента по ключу, ценой отсутствия гарантированного порядка обхода элементов.

Контейнеры-адаптеры (`stack`, `queue`, `priority_queue`) не являются самостоятельными структурами данных, а лишь ограничивают интерфейс одного из перечисленных выше последовательных контейнеров до строго определённой дисциплины доступа к его элементам (соответственно, стека — «последним пришёл, первым вышел»; очереди — «первым пришёл, первым вышел»; очереди с приоритетом — извлечение элемента с наибольшим приоритетом).

**Итераторы.** Обобщённые объекты, играющие по отношению к контейнеру роль указателя: они обеспечивают единообразный доступ к элементам контейнера и перемещение между ними, не завися при этом от конкретной внутренней организации этого контейнера. Именно благодаря итераторам один и тот же алгоритм STL оказывается применим к принципиально различным по внутреннему устройству контейнерам — итератор служит промежуточным, унифицирующим звеном между алгоритмами и контейнерами. Различают несколько категорий итераторов, образующих иерархию по степени предоставляемых возможностей: входные и выходные итераторы (минимальные возможности — однократный последовательный проход, только для чтения либо только для записи), однонаправленные (допускающие многократный проход в одном направлении), двунаправленные (допускающие движение как вперёд, так и назад) и итераторы произвольного доступа (допускающие непосредственный переход к произвольному элементу, подобно индексации обычного массива).

**Алгоритмы.** Обобщённые функции (объявленные, как правило, в заголовочных файлах `<algorithm>` и `<numeric>`), выполняющие типовые операции над данными, хранящимися в контейнерах, — сортировку, поиск, копирование, преобразование, накопление и подобные, — и оперирующие при этом не самими контейнерами напрямую, а парой итераторов, задающих обрабатываемый диапазон элементов, что и обеспечивает независимость алгоритма от конкретного типа контейнера.

**Функциональные объекты (функторы).** Объекты классов с перегруженным оператором вызова `operator()`, которые благодаря этому могут использоваться в качестве аргументов, подобных обычным функциям, — в частности, для настройки поведения обобщённых алгоритмов (задания пользовательского критерия сравнения при сортировке, условия отбора элементов и тому подобного). Начиная со стандарта C++11 в большинстве подобных случаев на практике удобнее применять лямбда-выражения — более компактный, встраиваемый непосредственно в место вызова синтаксис определения анонимной функции, содержательно решающий ту же задачу, что и функтор.

**Адаптеры.** Компоненты, видоизменяющие (адаптирующие) интерфейс уже существующего элемента STL под иные нужды, не изменяя его внутренней реализации: рассмотренные выше контейнеры-адаптеры представляют собой один из примеров такой адаптации; аналогично существуют адаптеры итераторов (например, `reverse_iterator`, обеспечивающий обход контейнера в обратном порядке) и адаптеры функций.

**Аллокаторы.** Вспомогательные объекты, инкапсулирующие стратегию выделения и освобождения памяти, используемую контейнером для хранения его элементов; по умолчанию контейнеры STL используют стандартный аллокатор общего назначения, однако при необходимости (например, для оптимизации под специфический паттерн использования памяти) аллокатор может быть заменён пользовательским.

### 3. Пример совместного использования компонентов STL

```c++
#include <vector>
#include <algorithm>
#include <map>
#include <iostream>

int main() {
    std::vector<int> numbers = {5, 3, 8, 1, 9, 2};

    // алгоритм sort, применённый к диапазону, заданному итераторами
    // begin() и end() контейнера vector, с лямбда-выражением
    // в роли пользовательского критерия сравнения (сортировка по убыванию)
    std::sort(numbers.begin(), numbers.end(),
              [](int a, int b) { return a > b; });

    for (int n : numbers) {
        std::cout << n << " ";
    }
    std::cout << "\n";

    // ассоциативный контейнер map для хранения пар "ключ - значение"
    std::map<std::string, int> ages;
    ages["Tom"] = 38;
    ages["Bob"] = 25;

    auto it = ages.find("Tom");   // алгоритм поиска, встроенный в сам контейнер
    if (it != ages.end()) {
        std::cout << it->first << ": " << it->second << "\n";
    }
}
```

Приведённый пример наглядно демонстрирует совместную, согласованную работу основных компонентов STL: контейнер `vector` хранит последовательность чисел; обобщённый алгоритм `sort` сортирует их, не зная заранее ничего о конкретном типе `vector`, а обращаясь к его элементам исключительно через переданную ему пару итераторов; лямбда-выражение выступает в роли функционального объекта, настраивающего критерий сортировки под конкретную задачу; а ассоциативный контейнер `map` демонстрирует альтернативный, основанный на ключевом доступе способ организации данных, также предоставляемый стандартной библиотекой шаблонов.
