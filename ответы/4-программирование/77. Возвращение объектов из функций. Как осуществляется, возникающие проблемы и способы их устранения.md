### 1. Способы возврата объекта из функции

Аналогично передаче параметров, рассмотренной в предыдущем вопросе, возврат результата работы функции может осуществляться одним из трёх способов: по значению, по ссылке или по указателю, — причём выбор конкретного способа существенно влияет как на эффективность, так и на безопасность программы.

### 2. Возврат по значению

Возврат по значению — наиболее употребительный и, как правило, наиболее безопасный способ возврата вновь созданного внутри функции объекта: выражение, указанное в операторе `return`, используется для инициализации временного объекта-результата непосредственно в месте вызова функции.

```c++
std::string BuildGreeting(const std::string& name) {
    std::string result = "Hello, " + name + "!";
    return result;
}
```

Исторически подобный возврат считался потенциально затратным, поскольку формально предполагал создание копии (либо, начиная с C++11, перемещение) локального объекта `result` в объект-результат вызова. На практике же современные компиляторы применяют оптимизацию исключения копирования (copy elision), устраняющую эти накладные расходы. Различают два родственных случая такой оптимизации: RVO (Return Value Optimization) — применяется, когда возвращаемое выражение представляет собой временный объект, создаваемый непосредственно в самом операторе `return` (например, `return Foo(args);`); начиная со стандарта C++17 данная оптимизация обязательна и гарантирована самим стандартом языка. NRVO (Named RVO) — применяется, когда возвращается именованная локальная переменная (как в примере с `result` выше); в отличие от RVO, эта оптимизация не гарантирована стандартом безусловно, но широко реализована во всех основных современных компиляторах.

Существен практический нюанс: не следует оборачивать возвращаемую локальную переменную в `std::move()` внутри оператора `return` (то есть писать `return std::move(result);`) — в большинстве случаев это, вопреки распространённому заблуждению, не ускоряет, а, напротив, препятствует применению компилятором оптимизации NRVO, вынуждая его прибегнуть к менее эффективному перемещению вместо полного исключения копирования.

### 3. Возврат по ссылке или по указателю

Возврат по ссылке или по указателю оправдан и эффективен в тех случаях, когда возвращаемый объект заведомо продолжает существовать и после завершения работы функции, — в частности, когда функция возвращает ссылку (указатель) на объект, переданный ей самой в качестве параметра по ссылке (указателю), на член объекта, для которого был вызван данный метод (через `this`), либо на статический или глобальный объект.

```c++
class Matrix {
public:
    double& At(int row, int col) {
        return data[row * cols + col];   // ссылка на элемент, хранящийся в объекте *this
    }
private:
    std::vector<double> data;
    int cols;
};
```

### 4. Проблема висячей ссылки (указателя)

Принципиально опасная ошибка возникает, когда функция возвращает ссылку или указатель на локальную переменную (объект с автоматической продолжительностью хранения), созданную непосредственно внутри самой этой функции, либо на временный объект. Память, отведённая под такую локальную переменную, освобождается сразу по завершении работы функции (при выходе из её области видимости), — тогда как возвращённая ссылка или указатель по-прежнему формально указывает на этот, уже недействительный участок памяти. Подобная ссылка (указатель) называется висячей (dangling); любое последующее обращение к ней приводит к неопределённому поведению программы — от кажущейся на первый взгляд корректной работы (пока соответствующий участок памяти случайно не оказался перезаписан чем-то иным) до аварийного завершения программы или трудно диагностируемого повреждения данных.

```c++
int& GetLocalValue() {
    int localVar = 42;
    return localVar;   // ОШИБКА: возвращается ссылка на локальную переменную
}                       // localVar уничтожается здесь, ссылка становится висячей

int& ref = GetLocalValue();
std::cout << ref;       // неопределённое поведение
```

Многие современные компиляторы способны распознать и предупредить об этой конкретной, синтаксически явной ошибке (выдав предупреждение вида «возврат ссылки на локальный временный объект»), однако подобное распознавание работает далеко не во всех случаях — в частности, оно легко ускользает от компилятора, если висячая ссылка формируется не напрямую, а опосредованно, через дополнительный уровень косвенности, — поэтому полагаться исключительно на предупреждения компилятора недостаточно, и требуется сознательное внимание разработчика к этой проблеме.

### 5. Способы устранения проблемы

**Возврат по значению для вновь создаваемых объектов.** Наиболее общая и надёжная рекомендация: если функция создаёт новый объект и должна вернуть его результатом своей работы, его следует возвращать именно по значению, полностью доверив вопрос эффективности компилятору (оптимизациям RVO и NRVO, рассмотренным выше), а не пытаться вручную «оптимизировать» это посредством возврата ссылки или указателя на локальную переменную.

```c++
// Исправленный вариант:
int GetValue() {
    int localVar = 42;
    return localVar;   // корректно: возврат по значению
}
```

**Возврат ссылки (указателя) только на данные, переживающие вызов функции.** Если по существу задачи действительно требуется вернуть ссылку или указатель (например, для реализации эффективного доступа к внутреннему элементу объекта без его копирования, как в примере с классом `Matrix` выше, либо для организации цепочки вызовов операторов, таких как `operator<<` или `operator=`), необходимо удостовериться, что возвращаемая ссылка (указатель) относится к объекту, который заведомо продолжит существовать после возврата из функции: члену объекта, для которого вызван метод; параметру, переданному функции по ссылке или указателю самим вызывающим кодом; либо статическому или глобальному объекту (с учётом сопутствующих рисков совместно используемого изменяемого глобального состояния).

**Динамическое выделение памяти с явным управлением владением.** Если возвращаемый объект должен продолжить самостоятельное существование за пределами вызова функции и не быть при этом жёстко привязанным к какому-либо уже существующему объекту, применяется динамическое выделение памяти (оператором `new`) с возвратом указателя на неё; при этом, во избежание утечек памяти, современная практика C++ настоятельно рекомендует возвращать подобный указатель не в «сыром» виде, а обёрнутым в один из умных указателей стандартной библиотеки (`std::unique_ptr`, реже `std::shared_ptr`), автоматически обеспечивающих корректное, гарантированное освобождение выделенной памяти по завершении её действительного использования.
