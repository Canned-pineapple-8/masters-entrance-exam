### 1. Понятие динамического программирования

Динамическим программированием называется метод решения задач оптимизации (или подсчёта числа вариантов), основанный на разбиении исходной задачи на более простые подзадачи, каждая из которых решается лишь однократно, а её результат сохраняется для последующего повторного использования, вместо того чтобы каждый раз заново вычисляться при повторном возникновении той же подзадачи. Метод применим к задачам, обладающим двумя ключевыми свойствами.

**Оптимальная подструктура.** Оптимальное решение исходной задачи может быть построено из оптимальных решений её подзадач меньшего размера — то есть глобально оптимальный результат складывается из локально оптимальных результатов составляющих его частей.

**Перекрывающиеся подзадачи.** При наивном рекурсивном решении задачи одни и те же подзадачи меньшего размера возникают многократно, в разных ветвях рекурсии. Именно наличие этого свойства принципиально отличает динамическое программирование от метода «разделяй и властвуй» (уже рассматривавшегося ранее применительно к сортировке слиянием и быстрой сортировке): в задачах, решаемых методом «разделяй и властвуй», подзадачи, на которые делится исходная задача, не пересекаются между собой, тогда как в задачах динамического программирования одна и та же подзадача способна встретиться в самых разных, не связанных напрямую частях общего дерева рекурсии, — и именно повторное, избыточное решение таких совпадающих подзадач наивным рекурсивным алгоритмом (нередко приводящее к экспоненциальной трудоёмкости) устраняется динамическим программированием за счёт сохранения уже вычисленных результатов.

### 2. Общая методика построения решения

Решение задачи методом динамического программирования, как правило, строится по следующей общей схеме.

**Шаг 1. Описание структуры (параметризация состояния).** Определяется, какими параметрами полностью характеризуется произвольная подзадача рассматриваемого семейства (то есть что именно составляет «состояние» подзадачи) — например, для задач над последовательностью это часто оказывается префикс последовательности заданной длины, для задач над двумя последовательностями — пара индексов в каждой из них, и так далее.

**Шаг 2. Построение рекуррентного соотношения.** Выводится формула, выражающая оптимальное значение (решение) для подзадачи данного размера через оптимальные значения подзадач меньшего размера, — именно этот шаг составляет содержательное ядро всего метода и требует наибольшего внимания: необходимо строго доказать (или, как минимум, содержательно обосновать), что оптимальное решение исходной подзадачи действительно всегда может быть построено путём комбинирования оптимальных решений одной или нескольких меньших подзадач согласно предлагаемой формуле.

**Шаг 3. Определение базовых (граничных) случаев.** Указываются тривиальные, минимальные по размеру подзадачи, для которых решение известно непосредственно, без обращения к рекуррентному соотношению (то есть база рекурсии).

**Шаг 4. Вычисление значений.** Значения для всех подзадач вычисляются в порядке, гарантирующем, что к моменту вычисления каждой конкретной подзадачи все меньшие подзадачи, от которых она зависит согласно рекуррентному соотношению, уже вычислены и сохранены.

**Шаг 5. Восстановление решения (при необходимости).** Если требуется не только оптимальное значение (например, максимальную стоимость), но и само оптимальное решение, порождающее это значение (например, конкретный набор выбранных предметов), дополнительно сохраняется информация о том, какой именно вариант рекуррентного соотношения был выбран оптимальным на каждом шаге, что позволяет впоследствии восстановить решение обратным проходом.

### 3. Два способа реализации

**«Сверху вниз» с мемоизацией.** Задача решается непосредственно рекурсивно, в соответствии с построенным рекуррентным соотношением, однако результат вычисления каждой подзадачи сохраняется (кэшируется) в таблице (массиве, ассоциативном контейнере) сразу после первого вычисления; при повторном обращении к той же подзадаче её результат немедленно извлекается из этой таблицы без повторного выполнения рекурсивных вызовов.

**«Снизу вверх» (табличный метод).** Задача решается итеративно, без явной рекурсии: сначала заполняются базовые случаи, а затем, в порядке возрастания размера подзадачи, последовательно вычисляются и сохраняются в таблице значения всё более крупных подзадач, вплоть до подзадачи, совпадающей с исходной. Этот способ, как правило, несколько эффективнее подхода «сверху вниз» (поскольку избавлен от накладных расходов на рекурсивные вызовы) и потому чаще применяется на практике.

### 4. Пример 1: числа Фибоначчи

Простейший иллюстративный пример, наглядно демонстрирующий проблему перекрывающихся подзадач. Рекуррентное соотношение общеизвестно: $F(n) = F(n-1) + F(n-2)$ при базовых случаях $F(0) = 0$, $F(1) = 1$. Наивная рекурсивная реализация этой формулы, не сохраняющая промежуточных результатов, обладает экспоненциальной трудоёмкостью $O(2^n)$, поскольку одни и те же значения $F(k)$ для меньших $k$ вычисляются многократно, в разных ветвях рекурсии.

```c++
int Fibonacci(int n) {
    std::vector<int> dp(n + 1);
    dp[0] = 0;
    if (n >= 1) dp[1] = 1;
    for (int i = 2; i <= n; ++i) {
        dp[i] = dp[i - 1] + dp[i - 2];   // рекуррентное соотношение
    }
    return dp[n];
}
```

Табличная реализация «снизу вверх», сохраняющая каждое значение $F(i)$ ровно один раз, снижает трудоёмкость до линейной, $O(n)$.

### 5. Пример 2: задача о рюкзаке (0/1 knapsack)

Классическая задача динамического программирования оптимизационного характера: дан набор из $n$ предметов, каждый из которых характеризуется весом $w_i$ и стоимостью $v_i$, и рюкзак вместимостью $W$; требуется отобрать подмножество предметов с максимальной суммарной стоимостью, суммарный вес которых не превышает $W$ (каждый предмет можно взять не более одного раза).

**Состояние.** $dp[i][w]$ — максимальная суммарная стоимость, достижимая с использованием первых $i$ предметов при ограничении на вес, равном $w$.

**Рекуррентное соотношение.** Для $i$-го предмета есть ровно два варианта: не включать его в решение (тогда $dp[i][w] = dp[i-1][w]$) либо включить его, если это допускает оставшаяся вместимость (тогда $dp[i][w] = dp[i-1][w - w_i] + v_i$); оптимальное значение выбирается как больший из этих двух вариантов:

$$
dp[i][w] =
\begin{cases}
dp[i-1][w], & \text{если } w_i > w, \\[4pt]
\max\bigl(dp[i-1][w],\; dp[i-1][w-w_i] + v_i\bigr), & \text{если } w_i \leqslant w.
\end{cases}
$$

**Базовый случай.** $dp[0][w] = 0$ для любого $w$ (при отсутствии предметов максимальная стоимость, очевидно, равна нулю).

```c++
int Knapsack(const std::vector<int>& weight, const std::vector<int>& value, int W) {
    int n = weight.size();
    std::vector<std::vector<int>> dp(n + 1, std::vector<int>(W + 1, 0));
    for (int i = 1; i <= n; ++i) {
        for (int w = 0; w <= W; ++w) {
            dp[i][w] = dp[i - 1][w];
            if (weight[i - 1] <= w) {
                dp[i][w] = std::max(dp[i][w], dp[i - 1][w - weight[i - 1]] + value[i - 1]);
            }
        }
    }
    return dp[n][W];
}
```

Итоговый ответ на исходную задачу содержится в ячейке $dp[n][W]$; трудоёмкость такого табличного решения составляет $O(n \cdot W)$, что кардинально эффективнее полного перебора всех $2^n$ подмножеств предметов, к которому свёлась бы задача при решении её без применения динамического программирования.
