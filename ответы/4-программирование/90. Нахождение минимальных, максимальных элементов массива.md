### 1. Постановка задачи

Пусть дан линейный (одномерный) массив из $n$ элементов, для которого требуется найти значение (а при необходимости — и позицию, индекс) минимального и максимального элементов. В общем случае массив предполагается неотсортированным — в противном случае задача становится тривиальной, поскольку минимальный и максимальный элементы отсортированного массива совпадают с его крайними элементами и находятся за постоянное время $O(1)$.
### 2. Поиск одного экстремума (максимума либо минимума)

Базовый алгоритм состоит в однократном последовательном просмотре всех элементов массива с сохранением текущего наибольшего (или наименьшего) из уже просмотренных значений: в качестве начального приближения берётся первый элемент массива, после чего каждый последующий элемент сравнивается с этим текущим приближением, и при обнаружении элемента, превосходящего его (либо, соответственно, меньшего его), приближение обновляется.

```c++
int FindMax(const std::vector<int>& arr) {
    int maxValue = arr[0];
    for (size_t i = 1; i < arr.size(); ++i) {
        if (arr[i] > maxValue) {
            maxValue = arr[i];
        }
    }
    return maxValue;
}
```

Данный алгоритм выполняет ровно $n-1$ сравнение и обладает трудоёмкостью $O(n)$. Существенно, что эта оценка является оптимальной для задачи поиска одного лишь экстремума: поскольку итоговый максимум должен быть заведомо не меньше любого другого элемента массива, каждый из оставшихся $n-1$ элементов обязан хотя бы однократно поучаствовать в сравнении (проиграть его), — то есть менее чем за $n-1$ сравнение корректность результата в общем случае гарантировать невозможно.

Если наряду со значением экстремума требуется определить и его позицию (индекс) в массиве, дополнительно заводится переменная, хранящая индекс текущего наилучшего найденного элемента и обновляемая одновременно с самим значением:

```c++
size_t FindMaxIndex(const std::vector<int>& arr) {
    size_t maxIndex = 0;
    for (size_t i = 1; i < arr.size(); ++i) {
        if (arr[i] > arr[maxIndex]) {
            maxIndex = i;
        }
    }
    return maxIndex;
}
```

### 3. Наивный одновременный поиск минимума и максимума

Если требуется одновременно найти и минимальный, и максимальный элементы массива, простейший подход состоит в объединении логики поиска обоих экстремумов в едином проходе по массиву:

```c++
void FindMinMax(const std::vector<int>& arr, int& minValue, int& maxValue) {
    minValue = maxValue = arr[0];
    for (size_t i = 1; i < arr.size(); ++i) {
        if (arr[i] < minValue) minValue = arr[i];
        if (arr[i] > maxValue) maxValue = arr[i];
    }
}
```

Такой наивный подход выполняет по два сравнения для каждого из оставшихся $n-1$ элементов массива, то есть в общей сложности порядка $2(n-1)$ сравнений.

### 4. Оптимизированный (турнирный) метод одновременного поиска

Число сравнений, необходимых для одновременного нахождения обоих экстремумов, можно сократить примерно на четверть посредством следующего приёма. Элементы массива разбиваются на пары; в пределах каждой пары за одно сравнение определяется, какой из двух элементов больше, а какой меньше. Далее максимум разыскивается уже не среди всех $n$ элементов, а лишь среди $n/2$ «победителей» (бо́льших элементов каждой пары), а минимум — лишь среди $n/2$ «проигравших» (меньших элементов каждой пары); поиск экстремума среди $n/2$ элементов, как показано выше, требует $n/2 - 1$ сравнение.

Суммарное число сравнений при таком подходе для чётного $n$ составляет:
$$
\underbrace{\frac{n}{2}}_{\text{разбиение на пары}} + \underbrace{\left(\frac{n}{2} - 1\right)}_{\text{поиск максимума}} + \underbrace{\left(\frac{n}{2} - 1\right)}_{\text{поиск минимума}} = \frac{3n}{2} - 2,
$$

что заметно меньше, чем $2(n-1) = 2n - 2$ сравнений наивного подхода, — данная оценка $\frac{3n}{2} - 2$ является теоретически доказанным оптимумом для задачи одновременного поиска минимума и максимума методом попарных сравнений. Для нечётного числа элементов один элемент остаётся без пары и должен быть отдельно учтён как при поиске максимума, так и при поиске минимума.

```c++
void FindMinMaxOptimized(const std::vector<int>& arr, int& minValue, int& maxValue) {
    size_t n = arr.size();
    size_t i = 0;
    if (n % 2 == 0) {
        if (arr[0] < arr[1]) { minValue = arr[0]; maxValue = arr[1]; }
        else                 { minValue = arr[1]; maxValue = arr[0]; }
        i = 2;
    } else {
        minValue = maxValue = arr[0];
        i = 1;
    }
    while (i + 1 < n) {
        int localMin, localMax;
        if (arr[i] < arr[i + 1]) { localMin = arr[i]; localMax = arr[i + 1]; }
        else                     { localMin = arr[i + 1]; localMax = arr[i]; }
        if (localMin < minValue) minValue = localMin;
        if (localMax > maxValue) maxValue = localMax;
        i += 2;
    }
}
```

### 5. Замечание о нижней границе трудоёмкости

Независимо от конкретного алгоритма поиска, задача одновременного нахождения минимума и максимума массива из $n$ элементов методом попарных сравнений не может быть решена менее чем за $\lceil 3n/2 \rceil - 2$ сравнения — этот факт установлен строго и представляет собой доказанную нижнюю границу трудоёмкости данной задачи, что делает рассмотренный выше турнирный метод асимптотически оптимальным (в отличие от наивного подхода, использующего примерно на треть больше сравнений, чем принципиально необходимо).
