### 1. Понятие палиндрома

Палиндромом называется строка, читающаяся одинаково как в прямом, так и в обратном порядке следования символов (например, «шалаш» или «madam»). Применительно к обработке строк рассматривают, как правило, две связанные, но различные задачи: проверку того, является ли вся заданная строка палиндромом целиком, и — существенно более содержательную задачу — поиск наибольшей по длине палиндромной подстроки внутри заданной строки произвольного вида.

### 2. Проверка строки на палиндром целиком

Простейшая задача решается методом двух указателей: один указатель устанавливается на первый символ строки, другой — на последний, после чего они последовательно сравниваются и сближаются к центру строки; если хотя бы одна такая пара символов не совпадает, строка палиндромом не является.

```c++
bool IsPalindrome(const std::string& s) {
    int left = 0, right = static_cast<int>(s.size()) - 1;
    while (left < right) {
        if (s[left] != s[right]) return false;
        ++left;
        --right;
    }
    return true;
}
```

Трудоёмкость данного алгоритма составляет $O(n)$, дополнительная память не требуется.

### 3. Поиск наибольшей палиндромной подстроки

**Наивный метод (полный перебор).** Рассматриваются все $O(n^2)$ возможных подстрок заданной строки, и для каждой из них за $O(n)$ проверяется, является ли она палиндромом (методом, рассмотренным выше); наибольшая среди найденных палиндромных подстрок и составляет ответ. Суммарная трудоёмкость такого наивного подхода составляет $O(n^3)$.

**Метод расширения от центра.** Существенно более эффективный подход, основанный на наблюдении, что всякий палиндром симметричен относительно своего центра, — а значит, вместо перебора всех подстрок можно перебирать все возможные центры палиндрома и «расширять» каждый из них наружу, пока символы по обе стороны от центра совпадают. Поскольку палиндром может иметь как нечётную длину (с центром непосредственно в одном из символов строки), так и чётную (с центром «между» двумя соседними символами), для строки длины $n$ рассматривается $2n - 1$ возможных центров.

```c++
std::pair<int, int> ExpandFromCenter(const std::string& s, int left, int right) {
    while (left >= 0 && right < static_cast<int>(s.size()) && s[left] == s[right]) {
        --left;
        ++right;
    }
    return { left + 1, right - 1 };   // границы найденного палиндрома
}

std::string LongestPalindrome(const std::string& s) {
    int bestLeft = 0, bestLen = 0;
    for (int center = 0; center < static_cast<int>(s.size()); ++center) {
        auto [l1, r1] = ExpandFromCenter(s, center, center);         // нечётный палиндром
        auto [l2, r2] = ExpandFromCenter(s, center, center + 1);     // чётный палиндром
        if (r1 - l1 + 1 > bestLen) { bestLeft = l1; bestLen = r1 - l1 + 1; }
        if (r2 - l2 + 1 > bestLen) { bestLeft = l2; bestLen = r2 - l2 + 1; }
    }
    return s.substr(bestLeft, bestLen);
}
```

Поскольку для каждого из $O(n)$ центров расширение занимает не более $O(n)$ шагов, общая трудоёмкость метода составляет $O(n^2)$ при дополнительной памяти $O(1)$.

**Метод динамического программирования.** Задача естественным образом укладывается в схему динамического программирования, рассмотренную в предыдущем вопросе. Состояние подзадачи $dp[i][j]$ определяется как логическое значение — является ли подстрока строки $s$ от индекса $i$ до индекса $j$ включительно палиндромом. Рекуррентное соотношение:

$$
dp[i][j] =
\begin{cases}
\text{true}, & \text{если } j - i < 2 \text{ и } s[i] = s[j], \\[4pt]
s[i] = s[j] \ \wedge\ dp[i+1][j-1], & \text{если } j - i \geqslant 2.
\end{cases}
$$

Содержательный смысл соотношения таков: подстрока является палиндромом тогда и только тогда, когда совпадают её крайние символы, а оставшаяся, «внутренняя» часть строки (после отбрасывания этих крайних символов) сама является палиндромом, — что в точности отражает рекурсивную, вложенную структуру палиндрома. Трудоёмкость такого табличного решения составляет $O(n^2)$ как по времени, так и по дополнительной памяти, — то есть асимптотически совпадает с методом расширения от центра, но требует бо́льших затрат памяти, поэтому на практике для данной конкретной задачи метод расширения от центра, как правило, предпочтительнее.

**Алгоритм Манакера.** Наиболее эффективный из известных алгоритмов решения данной задачи, предложенный Г. Манакером в 1975 году и работающий за строго линейное время $O(n)$. В основе алгоритма лежит переиспользование уже вычисленной информации о симметрии ранее найденных палиндромов: если для некоторого палиндрома с центром в позиции $c$ уже известны его границы, то для позиции $i$, симметричной относительно $c$ уже обработанной позиции внутри этого палиндрома, значение искомого радиуса палиндрома с центром в $i$ можно, за редкими граничными исключениями, сразу получить из уже вычисленного значения для симметричной ей позиции, не выполняя заново потенциально избыточные посимвольные сравнения. Именно это переиспользование ранее полученных результатов и позволяет алгоритму Манакера, в отличие от метода расширения от центра, избежать асимптотики $O(n^2)$, достигая линейной трудоёмкости $O(n)$ ценой существенно более сложной для понимания и реализации логики обработки граничных случаев.
