### 1. Общее понятие перегрузки операторов

Перегрузкой операторов называется механизм, позволяющий определить для объектов пользовательского класса собственную реализацию встроенных операторов языка (`+`, `-`, `*`, `<<`, `[]` и других), придав им содержательный смысл, применимый к этому классу. Функция, реализующая перегруженный оператор, именуется посредством ключевого слова `operator`, за которым следует символ самого перегружаемого оператора (например, `operator+`).

При перегрузке действует ряд ограничений: перегрузить можно исключительно операторы, уже существующие в языке (создать полностью новый, не предусмотренный синтаксисом C++ оператор невозможно); нельзя изменить число операндов оператора, его приоритет или ассоциативность; и, наконец, ряд операторов принципиально не подлежит перегрузке — в частности, оператор разрешения области видимости `::`, оператор доступа к члену `.`, оператор доступа к члену через указатель на член `.*`, тернарный условный оператор `?:` и оператор `sizeof`.

Функция, реализующая перегруженный оператор, может быть определена одним из трёх способов: как функция-член класса, как дружественная классу функция или как обычная (внешняя) функция, — каждый из которых рассматривается ниже.

### 2. Перегрузка с помощью функций-членов класса

При объявлении оператора в виде функции-члена класса неявный параметр `this` данной функции автоматически трактуется как левый операнд оператора, — поэтому такая функция-член принимает на один явный параметр меньше, чем формальное число операндов оператора: для бинарного оператора требуется указать лишь один явный параметр (правый операнд), а для унарного — ни одного.

```c++
class Dollars {
public:
    Dollars(int amount) : amount(amount) {}

    Dollars operator+(const Dollars& other) const {
        return Dollars(amount + other.amount);
    }

private:
    int amount;
};
```

Существенное практическое правило состоит в том, что ряд операторов — оператор присваивания (`=`), оператор индексации (`[]`), оператор вызова (`()`) и оператор доступа к члену через указатель (`->`), а также операторы явного и неявного преобразования типа, — по требованию самого языка C++ обязаны перегружаться исключительно в виде функций-членов класса; определить их в виде дружественной или внешней функции невозможно.

### 3. Перегрузка с помощью дружественных функций

Дружественная функция, объявленная внутри класса с ключевым словом `friend`, но определяемая (реализуемая) вне тела класса как обычная, не являющаяся его членом функция, получает прямой доступ к закрытым (`private`) и защищённым (`protected`) членам этого класса, минуя обычные ограничения инкапсуляции, рассмотренные в одном из предыдущих вопросов. Поскольку дружественная функция не является членом класса, у неё отсутствует неявный параметр `this`, — соответственно, для бинарного оператора такая функция принимает оба операнда в виде явных параметров.

```c++
class Dollars {
    friend Dollars operator+(const Dollars& a, const Dollars& b);
public:
    Dollars(int amount) : amount(amount) {}
private:
    int amount;
};

Dollars operator+(const Dollars& a, const Dollars& b) {
    return Dollars(a.amount + b.amount);   // прямой доступ к закрытому члену
}
```

Перегрузка посредством дружественной функции оказывается необходимой (либо, как минимум, существенно удобной) в двух характерных случаях. Во-первых, когда левый операнд оператора не является объектом того класса, для которого выполняется перегрузка (в частности, классический пример — оператор вывода в поток `operator<<`, у которого левый операнд имеет тип `std::ostream`, а не тип пользовательского класса, так что определить его как функцию-член пользовательского класса попросту невозможно):

```c++
class Point {
    friend std::ostream& operator<<(std::ostream& out, const Point& p);
public:
    Point(double x, double y) : x(x), y(y) {}
private:
    double x, y;
};

std::ostream& operator<<(std::ostream& out, const Point& p) {
    out << "(" << p.x << ", " << p.y << ")";
    return out;
}
```

Во-вторых, когда требуется обеспечить симметричное поведение оператора относительно порядка операндов разных типов (например, чтобы одинаково корректно обрабатывались как выражение `dollars + 5`, так и выражение `5 + dollars`) — функция-член класса, у которой левый операнд всегда неявно фиксирован как `this`, для такой симметрии не подходит без дополнительных ухищрений, тогда как дружественная (или внешняя) функция, принимающая оба операнда явными параметрами, легко перегружается в обоих необходимых сочетаниях типов параметров.

### 4. Перегрузка с помощью внешних (обычных) функций

Внешняя перегрузка оператора синтаксически почти полностью аналогична перегрузке посредством дружественной функции — с той лишь разницей, что такая функция не объявляется дружественной классу и, соответственно, не имеет прямого доступа к его закрытым членам; для реализации своей логики она вынуждена пользоваться исключительно открытым (публичным) интерфейсом класса — в частности, методами доступа (геттерами), рассмотренными в вопросе об инкапсуляции.

```c++
class Dollars {
public:
    Dollars(int amount) : amount(amount) {}
    int GetAmount() const { return amount; }
private:
    int amount;
};

Dollars operator+(const Dollars& a, const Dollars& b) {
    return Dollars(a.GetAmount() + b.GetAmount());   // доступ только через геттер
}
```

Такой способ перегрузки предпочтителен всякий раз, когда для реализации оператора достаточно уже имеющегося открытого интерфейса класса и не требуется прямой доступ к его внутреннему, закрытому состоянию: поскольку внешняя функция не наделяется никакими особыми привилегиями доступа, использование этого способа не ослабляет инкапсуляцию класса — в отличие от дружественной функции, добавление которой всякий раз расширяет круг кода, имеющего прямой доступ к внутренней реализации класса в обход его открытого интерфейса.

### 5. Сравнение и рекомендации по выбору способа

Три рассмотренных способа перегрузки операторов образуют своего рода иерархию предпочтительности с точки зрения качества инкапсуляции: там, где это принципиально возможно (операторы `=`, `[]`, `()`, `->`, требующие перегрузки исключительно в виде функции-члена, — не в счёт), предпочтение следует отдавать внешней (не дружественной) функции, если её реализация не нуждается в прямом доступе к закрытым членам класса; когда такой доступ действительно необходим, а левый операнд оператора при этом относится к типу самого класса, оправданным выбором становится дружественная функция; функцию-член класса, в свою очередь, естественно применять тогда, когда левый операнд оператора всегда заведомо является объектом данного класса, а симметричная обработка операндов разных типов не требуется. Существен и практический нюанс, связанный с симметричными бинарными операторами: если требуется поддержать оба порядка операндов разных типов (объект класса слева и справа от оператора), как правило, приходится определять две отдельные перегруженные версии оператора — по одной на каждый порядок следования типов операндов, — поскольку единственная функция-член класса способна обработать лишь тот порядок, при котором объект класса выступает левым операндом.
