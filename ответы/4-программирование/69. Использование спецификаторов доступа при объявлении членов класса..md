### 1. Синтаксис объявления доступа к членам класса

Каждый из трёх спецификаторов доступа (`public`, `protected`, `private`), рассмотренных в вопросе об инкапсуляции, указывается в теле объявления класса в виде ключевого слова, за которым следует двоеточие. Действие указанного таким образом спецификатора распространяется на все члены класса, объявленные непосредственно после него, вплоть до следующего встреченного спецификатора доступа либо до конца тела класса:

```c++
class Rectangle {
public:
    Rectangle(double width, double height);
    double GetArea() const;

private:
    double width;
    double height;
};
```

В данном примере конструктор `Rectangle` и метод `GetArea` относятся к открытой секции `public`, тогда как поля `width` и `height` — к закрытой секции `private`, поскольку они объявлены после соответствующего спецификатора.

### 2. Множественность и порядок секций

Существенная особенность языка C++ состоит в том, что спецификаторы доступа могут появляться внутри тела класса в произвольном порядке и произвольное число раз, — то есть допустимо, например, объявить сначала одну секцию `public`, затем секцию `private`, затем ещё одну секцию `public`, и так далее, — все члены, относящиеся к одному и тому же уровню доступа, при этом трактуются единообразно вне зависимости от того, сколько раз и в каком порядке соответствующий спецификатор встречается в тексте программы.

```c++
class Example {
public:
    void Foo();

private:
    int helperData;

public:
    void Bar();
};
```

На практике, тем не менее, принято группировать члены одного уровня доступа в единую секцию (а не чередовать их без необходимости), поскольку это облегчает восприятие структуры класса; распространены два противоположных стилистических соглашения — сначала объявлять открытый интерфейс класса (`public`), а затем закрытые детали реализации (`private`), либо, наоборот, сначала данные и вспомогательные закрытые члены, а затем открытый интерфейс, — конкретный выбор остаётся вопросом соглашения о стиле кода в рамках проекта, а не требованием языка.

### 3. Умолчание для `class` и `struct`

Если тело класса начинается с объявления членов до первого явного указания спецификатора доступа, действует умолчание, зависящее от того, каким ключевым словом объявлен сам класс: для `class` уровень доступа по умолчанию — `private`, для `struct` — `public`.

```c++
class A {
    int x;   // по умолчанию private
public:
    int y;   // явно public
};

struct B {
    int x;   // по умолчанию public
private:
    int y;   // явно private
};
```

Содержательно `class` и `struct` в C++ идентичны по всем прочим возможностям (оба могут иметь конструкторы, методы, участвовать в наследовании и так далее) и различаются исключительно этим умолчанием; выбор между ними на практике часто определяется соглашением: `struct` — для простых, преимущественно объединяющих открытые данные структур без существенной инкапсуляции, `class` — для полноценных классов с закрытым состоянием и определённым открытым интерфейсом.

### 4. Какие члены класса подпадают под спецификаторы доступа

Спецификаторы доступа единообразно применяются ко всем видам членов класса, объявляемых в соответствующей секции: полям (переменным-членам), методам (функциям-членам, включая конструкторы и деструктор), вложенным типам (вложенным классам, перечислениям, псевдонимам типов посредством `using` или `typedef`), а также статическим членам класса (переменным и функциям, связанным с классом в целом, а не с отдельным его объектом).

```c++
class Counter {
public:
    Counter() : count(0) {}
    void Increment() { ++count; }
    int GetCount() const { return count; }

    static int GetInstanceCount() { return instanceCount; }

private:
    int count;
    static int instanceCount;
};
```

Здесь статический метод `GetInstanceCount` относится к открытой секции наравне с обычными (нестатическими) методами, а статическое поле `instanceCount` — к закрытой, — то есть статус «статический» и уровень доступа представляют собой два независимых, ортогональных друг другу свойства члена класса.

### 5. Смысловое назначение каждого уровня при объявлении членов

Типовая практика организации класса состоит в том, чтобы объявлять в секции `public` конструкторы и методы, составляющие содержательный, предназначенный для внешнего использования интерфейс класса; в секции `private` — поля, хранящие внутреннее состояние объекта, а также вспомогательные методы, используемые исключительно самим классом для собственных внутренних нужд и не предназначенные для вызова извне (закрытые члены в этом смысле формируют не только скрытые данные, но и «закрытый интерфейс», используемый одними методами класса при реализации других его методов); секция `protected`, в свою очередь, применяется для членов, которые не должны быть частью открытого интерфейса класса, но должны оставаться доступными коду производных классов при последующем наследовании (рассмотренном в предыдущем вопросе) — типичный пример: защищённые вспомогательные методы или поля, которые базовый класс предоставляет производным классам для переиспользования при реализации их собственной, специфичной для них логики, не раскрывая эти детали произвольному внешнему коду.
